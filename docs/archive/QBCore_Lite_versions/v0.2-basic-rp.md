# v0.2 基础 RP

## 版本目标

在 v0.1 的稳定启动链上加入基础角色扮演功能，让服务器具备最小 RP 闭环。

重点不是堆功能，而是验证模块化加载方式可以逐步扩展。

## 实施范围

- 加入警察基础系统
- 加入医院基础系统
- 加入车辆钥匙
- 加入银行
- 加入基础职业
- 评估车库是否在本版本加入
- 记录每个资源的依赖和启动顺序

## 建议模块 cfg

```text

configs\modules\police.cfg
configs\modules\vehicles.cfg
```

## 功能边界

- 警察：先保留上岗、基础互动、基础执法。
- 医院：先保留倒地、治疗、复活流程。
- 银行：先保留账户查看、存取、转账。
- 车辆：先保留钥匙和基础车库，不急着加车店。
- 职业：先保留少量基础职业，避免一次性打开全部 job。

## 验收标准

- v0.1 的登录、出生、背包、HUD、语音不被破坏。
- 警察和医院职业能正常设置并使用基础功能。
- 银行能完成基础资金操作。
- 车辆钥匙和车库流程不出现阻塞级错误。
- 新增模块可以通过 cfg 独立启用或禁用。

## 风险点

- 警察、医院、门锁、监狱、MDT 之间可能有耦合。
- 车辆相关资源可能依赖车库、燃油、车店或数据库表。
- 银行和经济事件涉及资金安全，需要进入 v0.3 做统一审计。

## 已知问题记录

- **pma-voice 的 OneSync 依赖**：在 v0.1 中 `pma-voice` 因为没有开启 OneSync 导致无法启动。本版本已在 `server.cfg` 中添加了 `set onesync on`，完美解决了语音和 OneSync 状态依赖问题。
- **高级依赖暂缓**：`qb-phone`、`qb-doorlock`、`qb-prison` 已作为高级玩法暂缓，并不影响 v0.2 的基础 RP 最小闭环。
