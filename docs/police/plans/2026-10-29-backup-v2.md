# 计划：SM-06 NPC 支援 v2（生命周期 ack + 统一 TTL + 结束审计）

> 阶段 P。设计稿见 `docs/police/architecture/10-backup-v2.md`；本文只回答"怎么切、怎么验、怎么退"。
> 级别：**L3**（跨文件、新事件、状态结构变更），走 R → P → D → V → S。

## 1. 范围

**要做**

1. 结束原因（`ended.reason`）贯通客户端 → 服务端 → 审计；
2. 服务端持有阶段（`requested/spawning/enroute/onscene/engaged/ended`）与 `expires_at`；
3. 服务端 sweep：ack 超时释放、到点先 `BackupEnd` 再释放；
4. 客户端寿命不再自算，由服务端驱动；
5. 任务下发从"每 2.5s 重发"改成"任务状态门控 + 事件驱动"；
6. 可观测量：`GetNpcBudget()` 之外新增单位阶段投影，给 agent/MDT 读。

**明确不做**（防止膨胀，另开计划）

- 通缉玩家当目标（`10-backup-v2.md` §7.2）：需要跨资源契约（从 `custom-main` 拿 wanted 列表）+ 误伤不变量，**单独 L3 计划**；
- AI 质量（§7.3 `SetPedAsCop` / combat attributes）：纯客户端调参，**单独 L2**，但要实机确认不引出原生警察；
- 服务端生成实体 / routing bucket / 新表：见设计稿 §12 的否定理由。

> **读代码后的更正（2026-10-29）**：`backupUnits` 这个本地表**已经不存在**了。

## 4. 架构对照

- **平面**：P2 客户端（S1/S3/S4/S5）、P3 服务端（S1/S2/S3/S6）、P0 纯数据（S2 的 `backup_phases`）。不涉及 P4（不加表）。
- **跨平面契约变化**：
  - 新增事件 `police:server:backupAck`（client→server，session 鉴权，登记 `net_events_allowlist.json` 类别 `session`）；
  - 新增下发事件 `police:client:BackupEnd`（server→client，不登记）；
  - `police:server:backupEnded` 负载**向后兼容**新增 `reason`（旧客户端不发，服务端按 `unknown` 处理）；
  - 新增导出 `GetBackupState()`（只读投影，无 PII）。
- **宪法对照**：①服务端权威（阶段与释放只在服务端判定）③SQL 参数化（本次不新增 SQL）④事件鉴权（session + 白名单）⑤幂等（`Release` 已幂等；重复 ended 不二次释放）⑦诊断不回包（`backup.ack_rejected` 只写日志）⑧跨平面契约已在上表列明⑨先红后绿⑩交付三件套。

## 6. 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 阶段表与预算表不同步（预算已释放、阶段还留着，或反之） | 中 | 泄漏内存 / 状态与像素不一致 | 阶段表只在 `ended` 或 sweep 命中时删；以 `backupSlots(cid)`（读 `GetNpcBudget().entries`）为准；golden 覆盖「预算先释放」与「阶段先 ended」两个顺序 |
| ack 刷包 | 低 | netEvent 限流（50/200）可能误伤 | 服务端每 requestId 200ms 去重 + `backupDiag` 1 条/5s |
| sweep 释放与客户端 cleanup 撞车 | 中 | 二次释放/重复审计 | `Release` 幂等 + 审计只在状态由活动转 ended 时写 |
| 旧客户端（缓存）不发 reason/ack | 中 | 被当成异常 | 服务端把缺失 reason 记 `unknown`；ack 缺失走超时回收，不阻塞 |
| `BackupEnd` 到达时实体已被客户端删掉 | 高 | 无害 | 客户端 handler 幂等（`active[requestId]` 不存在直接返回） |
| 真机体验：5 分钟内到点被收 | 中 | 玩家觉得"支援突然没了" | 到点前 10s 给一次提示（chat/通知），reason=`expired` 写清 |
