# P4 证据与 bodycam · 施工方案（2026-10-31）

> 蓝图 P4 的原设计是「gunshot / damaged / panic 各触发 3 张图」。真机评估后改成两步走，
> 并明确 bodycam **只在按需与 panic 时拍照**。

## 1. bodycam 的必要性结论

| 方案 | 成本 | 收益 | 结论 |
|---|---|---|---|
| A 按需拍照（警员按一下，1 张） | 截图 100–300 ms / 次；150–400 KB / 张 | 每张图都"有故事" | **采用** |
| B 自动触发（蓝图原设计，3 张/事件） | 交火时每 3 张掉 0.5–1 s 帧 | 不用记得按 | **降级**：只保留 panic，1 张 / 30 s |
| C 纯元数据（无图） | ≈0 | 没有"画面"，RP 价值低 | 不做 |

已确认的三条约束（业主要求）：

| 项 | 取值 |
|---|---|
| 自动触发 | **只 panic**（倒地 / 报警），最多 1 张 / 30 s；**gunshot 不自动拍**（交火掉帧 + 噪音） |
| 保留期 | **7 天**，定时清理 |
| 存储 | **磁盘 + 路径入库**（DB 不存 BLOB） |

## 2. 第一步（本轮已做）：证据绑定收口

P3 遗留的债：酒测/药检读数读完就散 —— `police_evidence` 要求必须挂 case/incident/report
（`insertEvidence` 的 `missing_case`），而盘查发生在立案之前。

做法（不改表）：`police:server:fieldTest` 里查**这名警员当前正在处理的、未结的警情**
（`police_incident_units` join `police_incidents`，状态 open/assigned/enroute/on_scene），
有就调 `RegisterEvidence(source, { label, incident_id, location })` 挂上去，并把
`exhibit_no` 回给客户端显示；没有就只留审计，等立案后由 MDT「从最近盘查带入」（P3-3）。

真机：`refresh` + `restart custom-police` → SCRIPT ERROR 0。

## 3. 第二步：bodycam 本体（下一轮）

| 步 | 内容 |
|---|---|
| P4-1 | `screenshot-basic` 截图（只截 3D 世界）→ 带 token 的上传路由（复用 `custom-director` 的 `SetHttpHandler`，限大小/频率） |
| P4-2 | 落盘 `evidence/<yyyy-mm>/<exhibit>.jpg` + 路径入 `police_evidence`；`sha256` 写进 `police_evidence_chain` |
| P4-3 | 客户端：按需快门（1 张 / 10 s/人）+ panic 自动（1 张 / 30 s） |
| P4-4 | 7 天清理线程 + 平板证据页显示缩略图 |
