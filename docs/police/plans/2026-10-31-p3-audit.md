## 1. 结论

P3 的四块内容里，**三块已经存在**，缺的是"在街上对一个真人做盘查"这条交互路径：

* 逮捕 / 报告 / 罚单 / 证据 四个表单都在手机 MDT 里（`PoliceMDT.svelte` 的 `report` 页，四个子页）；
* BOLO 发布在 `p2_system.lua`（`bolo.create` 策略）；
* 罚单金额与刑期以 `Config.Justice.Crimes` 为准，`citations.lua` 与 `p3_cases.lua` 都走同一份。

## 3. 真缺口 = 一条交互路径

现在警员要盘查一个人，只能靠聊天命令或 MDT 里手打 citizenid。缺的是：

```
对准玩家 → 看到「查证件 / 搜身 / 酒测 / 药检 / 铐起 / 押送」
       → 服务端复验（距离 ≤3 m、在岗、目标在线）
       → 结果落在证据/案卷上，而不是只在两个人屏幕上飘一句
```

## 4. 施工切分

| 步 | 内容 | 工时 | 依赖 |
|---|---|---|---|
| **P3-1** | 玩家 qb-target 面板（查证件 / 搜身 / 铐起 / 押送）+ 服务端距离与在岗复验 | 1 天 | 无 |
| **P3-2** | 酒测 / 药检：动作 + 结果写入 evidence（含阈值与冷却） | 1 天 | P3-1 |
| **P3-3** | 盘查结果一键带入逮捕表单（citizenid + 现场证据预填） | 半天 | P3-1、P3-2 |

## 5. 验收判据（先写后验）

| 编号 | 判据 |
|---|---|
| AC-P3-01 | 对准任意在线玩家 MUST 出现靶心选项；对 NPC 世界守卫不出现（避免误伤布景） |

## 7. P3-2 酒测 / 药检（2026-10-31）

### 7.1 先解决数据源

本服没有 `qb-smallresources`，也没有任何"喝醉"状态 —— 酒测没有数据源就只能编随机数，那比没有更糟。
所以补了一个最小实现 `server/sobriety.lua`：

| 项 | 值 |
|---|---|
| 数据源 | `qb-inventory:server:UseItem` + `GetItemByName` 归属校验（没这瓶酒就不上头） |
| 物品 | `beer +0.25`、`vodka +0.50` |
| 衰减 | 每秒 -0.01 |
| 分档 | `<0.20` 清醒 / `0.20–0.50` 微醺 / `>0.50` 醉 |

药检读目标的 `metadata.drug_level`（本服暂无药物系统，读数为 0 = negative）。

### 7.2 回调

`police:server:fieldTest(source, cb, targetSrc, kind)`：

1. 在岗警察（离岗 → `off_duty`）
2. 目标在线
3. **服务端复算距离**（>3.5 m → `too_far`）
4. 同类读数 60 s 冷却（`RateLimitCooldown`，owner 是 core-framework）
5. 结果写 `police_audit`（`fieldtest.alcohol` / `fieldtest.drug`）

**刻意不写 `police_evidence`**：`insertEvidence` 要求必须挂 `case_id` / `incident_id` / `report_id`，
而盘查发生在立案之前。证据绑定留给 P3-3（盘查 → 立案 → 把读数挂上去）。

### 7.3 真机

`refresh` + `restart custom-police` → **SCRIPT ERROR 0**，资源 86/116。
