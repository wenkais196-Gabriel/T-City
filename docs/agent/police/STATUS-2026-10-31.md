## 2. 真正的缺口（按代码查过，不是猜）

| # | 缺口 | 证据 | 影响 |
|---|---|---|---|
| 1 | **P6 一个动作都没有** | `grep query_case|draft_report|issue_warrant` = 0 | agent 只能看板，不能干活 |
| 2 | **没有 bodycam** | `grep -i bodycam` = 0 | 案卷只有文字，没有"当时画面" |
| 3 | **没有指纹 / DNA** | 只在 evidence 文案里有字符串，无采集流程 | 现场只能靠口供与目击 |
| 4 | **没有保释 / 假释** | `grep bail|parole` = 0 | 关进去就只能等刑期 |
| 5 | **盘查读数没挂证据**（P3 遗留） | `insertEvidence` 要求 case/incident/report，盘查发生在立案前 | 酒测/药检读完就散了，案卷里没有 |
| 6 | 证据的"取证入口"不全 | MDT 有证据页；现场采集靠 `evidence.lua` 的状态叠加 | 需要对着 case 挂证据的动线 |
| 7 | 多机验收欠账 | P2-04/06/07/09、P3 全部交互 | 单客户端无法验证 |

## 3. 建议顺序

| 顺序 | 做什么 | 为什么先做它 | 工时 |
|---|---|---|---|
| **①** | **P4 证据收口**：盘查读数延迟绑定到案卷 + 证据挂 case 的动线 | 它直接关掉 P3 的遗留 5，且是 bodycam 的前置 | 1–2 天 |
| ② | P4 bodycam（gunshot/damaged/panic 触发 3 张图） | 让案卷"有分量"，但要先有 ① 的绑定 | 2 天 |
| ③ | P6 agent 三个动作 + AI 调度员草稿 | 差异化最大；依赖 P3 的报告模板（已有） | 2–3 天 |
| ④ | 指纹 / DNA | 玩法深度，但需要采集物品与 UI | 2 天 |
| ⑤ | 保释 / 假释 | 司法闭环，依赖法院侧 | 1–2 天 |
