# 09 — 任务的三种入口：日常是货架、剧情是剧本、奇遇是天气

> **核心命题**: 任务系统的差别不在内容多少，而在**谁发起、玩家怎么被叫到现场、他能反悔多久**。
> **适用范围**: custom-quest 的模板分类、手机任务 App、story-engine 派发、未来的 encounter_director。
> **状态**: 设计已定方向（2026-10-26），实现排入 P4，尚未开工。

---

## 1. 现在的问题

任务接取是**一步到位**的：手机点「接取」按钮 → 直接进入第一个目标。

这对日常任务是对的（玩家主动、目的明确）。但对另外两类是错的：

- 剧情任务从手机列表里"自己冒出来"，等于让玩家给自己派剧本，破坏叙事节奏；
- 奇遇如果直接弹一个"接取 / 拒绝"，那是问卷，不是遭遇。

所以在"世界告诉你有事"和"目标正式生效"之间，需要一层**可控的过渡**。

---

## 2. 预开始的四个阶段

| 阶段 | 玩家体验 | 谁推进 | 能反悔 | 结束条件 |
|---|---|---|---|---|
| lead 线索 | 收到短信 / 路过瞥见 / NPC 搭话 | 系统 | 能（无视即消失） | 线索 TTL |
| contact 接触 | 走到地点，找到那个人、车或门 | 玩家 | 能（离开即放弃） | 现场窗口 |
| briefing 准备 | 对话、等待、装作没事发生 | 玩家 + 系统 | 能 | 窗口结束 |
| active 生效 | 目标出现，进入正常任务流程 | 系统 | 需走放弃流程 | 完成或失败 |

四条硬规则：

1. **预开始不产生收益，也不消耗每日次数。** 次数在 active 开始时才扣——否则玩家看一眼就算用掉一次。
2. **每段都能退出，退出没有惩罚。** 不能退出的引导不是引导，是强制拉人。
3. **contact 之后要落盘。** 玩家下线再回来能续接，否则中途断线等于任务作废。
4. **窗口要短。** 奇遇现场 ≤ 90 秒，剧情引导 ≤ 5 分钟。把人锁在一个点上等，是最糟的体验。

---

## 3. 三类任务各走哪条门

### 3.1 daily（日常）— 手机货架

点「接取」立即生效，中间只有一张**任务简报卡**：目的、报酬量级、预估时长、需要满足什么。

不做预开始：玩家自己点的，他知道自己要什么。反悔走已有的放弃流程。

### 3.2 story（剧情）— 剧本，只能被递到手上

**剧情任务不出现在手机的任务列表里。手机只作为线索接收器。**

两种递法，按章节调性选，不强行统一：

- **NPC 面交**（章节开头）：手机收到一条消息而不是任务卡——"某某想见你，老地方"，带人名和地点；到点找 NPC 交互；对话本身包含决策点，玩家那句承诺就是接取动作。
- **短信下达**（章节中段接头）：匿名短信"三点，码头三号仓，别带人"，只有时间和地点；到点后原地等待，等待结束目标才出现。

### 3.3 encounter（奇遇）— 天气，不能预约

- 由世界触发，判定可以是位置、时间、事件、随机，**也可以组合**。
- 玩家收到的是提示而不是任务：一句推送，或地图上一个临时标记。
- 现场有一个短窗口，进去才开始；错过没有任何惩罚，只是这次没遇上。

---

## 4. 奇遇的五个样板

| 奇遇 | 触发组合 | 预开始 | 正式流程 | 奖励 | 调性 |
|---|---|---|---|---|---|
| 抛锚的货车 | 位置 + 时间（20:00–04:00） | 冒烟的货车与挥手的司机 | 帮修 30 秒，或帮他叫拖车抽成 | 亲手修 $300–600 + 修车声望；叫拖车 $150 零风险 | 低风险日常感，新手对"世界是活的"的第一印象 |
| 巷子里的赌局 | 位置 + 随机（15%） | 三人围着纸箱，一人抬下巴 | 坐下，三局牌（决策 ×3，胜率 45%） | 赢 $500–1500 / 输 $200，下注额自选 | 灰色地带，穷玩家翻身的路 |
| 让开，警察来了 | 事件（附近有追捕）+ 位置 | 警察喊话 + 临时标记 | 帮忙堵巷口，或让开 | 见义勇为 +$200 + 警察声望 | 唯一"被别人的故事卷进去"的一条 |
| 码头搬货 | 位置 + 时间 + 身份（非警察） | 工头招手："缺个人手，两小时" | 搬 5 箱，每箱 20 秒 | $400–800，被巡逻警察看到会触发盘查 | 给"没任务但想挣钱"的人一条低门槛路 |
| 路边的旅人 | 随机 + 位置（白天 2%） | 有血迹的人坐在路边招手 | 送医 / 给钱 / 无视三分支 | 送医 $500 + 医疗声望；给钱只有一句谢谢 | 唯一鼓励做好事、且选择会被世界记住的一条 |

三档"被记住"的伏笔（需要跨次存储）：

- 赌局：连续拒绝两次，这条巷子对该玩家永久关闭；
- 旅人：无视之后，下次遇到时他已经死了；
- 货车：帮过一次之后，同一个司机可能再次出现并主动加价。

## 5. 技术改动清单

| 改动 | 说明 | 依赖 |
|---|---|---|
| 模板加 kind | daily / story / encounter，默认 daily 以兼容现有 49 条 | 无 |
| 模板加 lead 定义 | 入口类型（npc / sms / world）、地点、等待秒数、现场 TTL | 无 |
| player_quests 加 phase | lead / contact / briefing / active，支持下线续接 | 一条迁移 |
| 接上每日次数 | conditions.daily_limit 与 quest_daily_limits 已有表和函数，零调用者 | 无 |
| encounter_director | 候选池 + 组合条件判定 + 全局与个人两级冷却 | 事件总线 |
| 手机消息 | phone_notifications 表已在，缺"发件人"概念 | 小改 |
| NPC 交互 | qb-target 已在，缺 NPC 生成与台词表 | 内容工作 |

现有的步骤类型已经够用：reach、interact、wait、deliver、combat、decision、placement 都在使用中，"等接头""三局牌""搬箱子"都能直接表达，不需要新的执行器。

## 6. 待拍板

1. 五个奇遇保留哪几条、哪几条换题材；
2. 剧情用 NPC 面交还是短信，或按章节混用（建议混用）；
3. "被记住"的跨次伏笔值不值得做（工作量在存储与清理）；
4. 预开始的最长等待（建议奇遇 90 秒、剧情 5 分钟）。

拍板后按 P4-1（分类与次数）→ P4-2（剧情收口）→ P4-3（奇遇）推进，每一步都能单独验收。
