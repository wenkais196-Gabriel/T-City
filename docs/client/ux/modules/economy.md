# 经济与交易 · UX 设计

> 覆盖 `qb-shops`（便利店/酒类/五金）、`qb-banking`、`custom-market`（动态交易市场）、
> `qb-pawnshop`（当铺）、`core_economy`（金额网关）。

## 1. 调研（现状）

### 1.1 玩家能花钱的地方

| 场所 | 打开方式 | 反馈 | 依据 |
|---|---|---|---|
| 便利店 / 酒类 / 五金 | **两条入口**：走近按 `E`（`IsControlJustPressed(0,38)`）+ 注册了 qb-target 热区（ALT） | 购买成功只弹一条 `QBCore:Notify` | `T-CityLite.base/resources/[qb]/qb-shops/client/main.lua`:33、`:51`、`:204` |
| 银行柜台 | ALT 热区（`Open Bank`） | 面板内提示 | `qb-banking` |
| 当铺 | ALT 热区（`Pawn Shop`） | 面板内提示 | `qb-pawnshop` |
| 动态市场 | 命令/App 入口 | 面板内 | `custom-market` |
| 罚款 / 工资 | 服务端事件 | `QBCore:Notify` 一条 | `T-CityLite.base/resources/[qb]/qb-core/server/services/economy_service.lua`:54 |

### 1.2 玩家会卡住的场景

| # | 场景 | 现在 |
|---|---|---|
| 1 | 站柜台前不知道按 E 还是 ALT | 两条入口并存，提示一条是 DrawText、一条是 ALT 面板 |
| 2 | 钱不够 | 通知一闪而过，与"买到了"长得一样（同一条通道） |
| 3 | 买完不知道余额 | 只有 HUD 在"钱变化时"闪一下，常驻余额不显示 |
| 4 | 银行入账凭证 | 只在手机通知中心，屏幕无提示 → 玩家以为没到账 |
| 5 | 商店是否存在 | 2026-11-10 之前 `qb-shops` 根本不在启动集 → 全服零商店 |

## 2. 设计（目标）

### 2.1 交易流程（一次购买）

```
走近柜台 → prompt: [E] 打开商店
      → 面板选择商品 → 确认
            ├─ 成功 → feed: "支付 −$2 · 水 1 瓶 · 余额 $516"（金额绿色高亮）
            └─ 失败 → error: "现金不足，还差 $48"（左下红，不打断）
      → 面板关闭 → 提示回到 [E] 打开商店
```

### 2.2 规则

| 事件 | 通道 | 文案格式 | 备注 |
|---|---|---|---|
| 购买成功 | `feed` | `支付 −$2 · <物品> ×N · 余额 $516` | `icon='$'` 让色条变绿 |
| 出售/收入 | `feed` | `收入 +$120 · <来源>` | 同上 |
| 余额不足 | `error` | `现金不足，还差 $48` | 永不 toast |
| 无权限/职业限制 | `error` | `这家店只卖给 <职业>` | — |
| 银行入账 | `phone` | `<来源> 入账 $5,000` | 只在手机通知中心，可回查 |
| 工资发放 | `feed` | `工资 $100（LSPD · 值班）` | 与交易同通道 |
| 罚款 | `toast` | `罚款 $500 · <事由>` | 需要停一下知道 |

### 2.3 交互与空态

| 情形 | 表现 |
|---|---|
| 柜台前 | 只有一条 `[E] 打开商店`（**去掉 ALT 热区**） |
| 商店无货（`useStock=true` 且库存 0） | 面板内显示"售罄"，不弹 error |
| 面板加载中 | 骨架/转圈 + "正在取货架…" |
| 面板请求超时 | 页内提示"网络忙，稍后再试" + 保留面板（可重试） |

## 3. 计划（任务）

| # | 任务 | 文件 | 风险 | 验收 |
|---|---|---|---|---|
| E-1 | `qb-shops` 去掉 ALT 双入口，只留 E | `qb-shops/client/main.lua:33,51-69,189` | 低（去掉一段注册） | 柜台前只出现一条 E 提示 |
| E-2 | 购买/出售结果改走 `feed`（金额高亮） | `qb-shops/client`（面板回调处） | 低 | 买水后左下 feed 带余额 |
| E-3 | 余额不足改走 `error` | 同上（失败分支） | 低 | 钱不够时左下红条，不弹 toast |
| E-4 | 银行入账改走 `phone`，并要求凭证可回查 | `qb-banking/server` | 中（要确认凭证落库） | 转账后手机通知中心有记录 |
| E-5 | 工资/罚款分别迁 `feed` / `toast` | `T-CityLite.base/resources/[qb]/qb-core/server/services/economy_service.lua`、罚款调用点 | 中（调用点多） | 发工资与罚款表现不同 |

## 4. 验收（步骤）

1. 走到 24/7 柜台：**只看到** `[E] 打开商店`，对着同一个柜台按 ALT **不应该**出面板；
2. 买一瓶水（$2）：左下 feed 出现"支付 −$2 · 余额 $516"，钱从 518 → 516；
3. 把钱花到不足：再买贵的东西 → 左下 **红条**"现金不足，还差 $X"，**没有**中央 toast；
4. 让另一角色转 $1000 给自己：手机通知中心出现入账记录，屏幕**不弹**；
5. 到点领工资：左下 feed 出现工资条目（不是 toast）。

## 5. 已知未决

- `custom-market` 的动态价格（供需）没有在 UI 上解释"为什么贵了"，玩家会以为被坑；
- 罚款的事由文案是英文 locale 拼接，中文下会出现混排（待统一）；
- 当铺的"估价"与"实际到账"不一致时缺解释。
