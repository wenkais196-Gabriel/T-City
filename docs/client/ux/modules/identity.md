# 角色与出生 · UX 设计

> 状态 **draft**：§1 调研进行中（我的部分已入库，等 CC 的仓库流程拆分）。
> 工作流见 [00-workflow.md](../00-workflow.md)。

## 1. 调研（现状）

### 1.1 触点规模（实测）

| 资源 | 通知类调用 | 交互热区 | 命令 |
|---|---|---|---|
| `qb-multicharacter` | 4 | 0 | 3 |
| `qb-spawn` | 6 | 0 | 2 |
| `qb-apartments` | 9 | 2 | 0 |

### 1.2 角色卡的数据从哪来（$818 vs $518 的根因）

`qb-multicharacter` 的 `qb-multicharacter:server:setupCharacters` 直接
`SELECT * FROM players WHERE license = ?`，再把 `money`/`job`/`position` 逐个 `json.decode` 回给 UI。

也就是说：**角色卡显示的是数据库快照**，而玩家进游戏后看到的是 `qb-core` 内存里的实时值。
两者只在下线保存时才对齐 —— 上一局没走到保存（崩溃、强退、被踢），卡片就会显示旧金额。
真机那次 $818（卡片） vs $518（游戏内）就是这么来的，**不是"数据源不同步"这种模糊说法，而是"卡片读历史快照"**。

### 1.3 删除角色的现状

qb-multicharacter 的 html/app.js 是两步：`prepareDelete` → `delete_character`。但确认页（html/index.html:155）
只有一句 `deletechar_description` + 一个确认键，**不显示角色名、不要求输入任何东西**。
误删的代价是整条角色数据（背包/车/房产/银行），而界面上和"取消"一样点一下就完事。

### 1.4 出生流程与"救援"文案

`qb-spawn` 的出生流程由服务端 `qb-spawn:server:GetLastLocation` 与本机 `insideMeta` 决定：
公寓 → `qb-apartments:client:LastLocationHouse`；房产 → 交给 `qb-interior` / `qb-houses` 传送。
**玩家在这个过程里没有任何选择**（没有出生点选择界面），也没有"你在哪"的交代。

另外 `qb-spawn` 里有一批"救援"提示，文风与世界观脱节：

| 位置 | 文案 |
|---|---|
| `qb-spawn/client.lua:92` | 「检测到空间裂缝，您已被引力安全拉回市区中心。」 |
| `:100` | 「检测到您在水中上线，水下呼吸气泡已充盈，请尽快游出…」 |
| `:110` | 「检测到高空坠落危机，紧急救生备用伞包已自动配给。」 |
| `:592` | 「检测到您坠入虚空空间，已安全将您重置回市区。」 |

它们是**系统兜底**，不是玩家动作的结果，混在同一个通知样式里等于告诉玩家"服务器出 bug 了"。

### 1.5 玩家会卡住的场景

| # | 场景 | 现在 |
|---|---|---|
| 1 | 卡片金额与进游戏后不一致 | 卡片读 DB 快照，不标注"上次保存" |
| 2 | 删角色 | 确认页不显示角色名，点一下就删 |
| 3 | 出生 | 无选择、无交代；落地后不知道自己在哪 |
| 4 | 被救援传送 | 「空间裂缝」这类文案让人以为服务器坏了 |
| 5 | 公寓交互 | 2 个热区仍走 qb-target 的 ALT |

### 1.6 外部实践（我的调研，2026-11-11）

| 来源 | 关键做法 | 对我们的意义 |
|---|---|---|
| **Agency《FiveM Multicharacter System》** | 角色数据必须与玩家数据**分离**，角色表是唯一事实源；角色选择界面是"服务器给人的第一印象"，必须做对 | 卡片读 DB 没错，错在**不告诉玩家这是快照**。要么标"上次保存"，要么在选人前强制落库 |
| **9AM《Spawn Selector》** | 出生选择器给三类选项：**上次位置 / 家或公寓 / 2–3 个区域**；明确建议**列表保持短**（四五个强选项胜过十五个没人用的）；数据在客户端缓存，重启洪峰也能秒开 | 我们连选择都没有。按 9AM 的清单做：上次位置 + 公寓 + 市区，最多 5 个 |

**外部结论三条**：

1. **卡片要标注数据时间**："上次保存 12 分钟前 · \$518"，不一致就从"bug"变成"说明"；
2. **删除必须让人确认身份**：显示角色名与 citizenid，并要求输入角色名；
3. **出生是一次选择**：不给选择的出生点，玩家只能在落地后自己找方向。

## 2. 设计（目标）

> 综合 §1.2–1.6。一句总纲：**这个模块的所有问题都是"没交代清楚"** ——
> 卡片不说数据多旧、删除不说删的是谁、出生不说你在哪。

### 2.1 角色卡：标注数据时间，而不是假装实时

| 项 | 决策 |
|---|---|
| 数据源 | **保持 DB 快照**（离线角色本来就没有内存态，改成"实时"是假的） |
| 新增 | 卡片底部一行：`上次保存 · 12 分钟前`（来自 `players.last_updated`） |
| 金额 | `dollar.format` 已经是整数显示，不动 |
| 为什么 | 快照 + 时间戳 = 玩家能理解"这是上次的记录"；只给数字 = 玩家以为服务器算错了 |

### 2.2 删除角色：确认页必须让人确认"删的是谁"

| 项 | 现在 | 改成 |
|---|---|---|
| 显示 | 一句 `deletechar_description` | 角色名 + citizenid + 出生日期 |
| 确认方式 | 点「确认」按钮 | **输入角色名**（逐字相等才启用按钮），并显示"不可恢复"红字 |
| 取消 | 「取消」 | 保留，且在弹层任意处按 Esc 取消 |

**为什么不能用通知承担确认**：通知是"单向告知"，没有输入通道；删除是不可逆动作，
必须有一步"人主动做的输入"。这也是全模块唯一需要打字确认的地方。

### 2.3 出生：给选择，并交代你落在哪

| 项 | 决策 |
|---|---|
| 选项 | **上次位置**（默认选中）/ **公寓**（有房产才出现）/ **市区**（Legion Square），最多 3 个 |
| 数量 | 不超过 5 —— 9AM 的实践：四五个强选项胜过十五个没人用的 |
| 选完 | `toast`「你出生在 <地点名>」+ 背景黑屏淡出，不弹 error |
| 首次进入 | `toast`「这是你第一次进入城市：按 M 打开手机，按 E 与环境交互」 |
| 不做的 | 不做地图预览/镜头飞行 —— 那是新 UI，成本高、收益低（玩家只选一次） |

### 2.4 救援兜底：换成世界观内的文案，并归到 `toast`

| 位置 | 现在 | 改成 |
|---|---|---|
| 虚空/裂缝 | 「检测到空间裂缝，您已被引力安全拉回市区中心。」 | 「你被送回了市区（位置异常）」 |
| 水中上线 | 「检测到您在水中上线，水下呼吸气泡已充盈，请尽快游出…」 | 「你在水里上线了，先上岸」 |
| 高空坠落 | 「检测到高空坠落危机，紧急救生备用伞包已自动配给。」 | 「你从高处落地，已自动稳住」 |

通道：`toast`（需要停一下看清楚），**不是 error** —— 玩家没做错什么。

### 2.5 公寓热区 → `[E]`

`qb-apartments` 的 2 个热区都是单动作（进公寓 / 用衣柜），按 D2 改成 `custom-prompt` 的 `[E]`。


## 3. 计划（任务）

| # | 任务 | 文件 | 风险 | 验收 |
|---|---|---|---|---|
| I-1 | 角色卡显示「上次保存 · N 分钟前」 | qb-multicharacter 的 server/main.lua（下发 last_updated）+ html/index.html + html/app.js | 低 | 卡片底部有时间；改库后重连时间更新 |
| I-2 | 删除确认：显示角色名/citizenid + 输入角色名才能删 | qb-multicharacter 的 html/index.html + app.js | 中（Vue 模板改动） | 输错名字按钮不可点；输对才删得掉 |
| I-3 | 出生选择（上次位置 / 公寓 / 市区）+ 落地 toast | qb-spawn 的 client.lua + html；qb-apartments 联动 | **高**（新 UI + 传送链路，可能踩黑屏/无敌 bug） | 三个选项都能落地且不卡黑屏 |
| I-4 | 救援文案世界观化，归 `toast` | qb-spawn 的 client.lua（4 处） | 低 | 文案不再出现"空间裂缝" |
| I-5 | 公寓热区改 `[E]` | qb-apartments 的 client | 中 | 站到公寓门口出现 `[E]` |

**顺序**：I-1（低风险高收益）→ I-4（纯文案）→ I-2（删除保护）→ I-5 → I-3（最大，单独一轮）。

**I-3 的风险要先说清**：`qb-spawn` 现在有强制无敌、强制淡入、剔除载具碰撞等一串兜底补丁
（本文件 §1.4 可见），插入一个选择界面要在 `PlayerLoaded` 之后、`GetLastLocation` 之前拦住流程，
写错就是**全服黑屏**。所以它单独一批，先在测试服上只对开发账号开放。
