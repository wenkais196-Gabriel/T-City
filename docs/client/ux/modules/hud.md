## 1. 调研（现状）

### 1.1 触点规模（实测）

| 资源 | 通知类调用 | 交互热区 | 命令 |
|---|---|---|---|
| `qb-hud` | 14 | 0 | 6 |
| `qb-scoreboard` | 2 | 0 | 3 |

### 1.2 玩家会卡住的场景

| # | 场景 | 现在 |
|---|---|---|
| 1 | 看余额 | 钱**只在变化时**闪一下（PO 明确要求保持这样），常驻余额不可见 |
| 2 | 看饥渴 | 四个圆环只有颜色，没有数值；快饿死和刚吃饱看着差不多 |
| 3 | 战斗中被通知切断视野 | 中央 toast 2.5 秒，压在准星上方 |

### 1.3 为什么"只有颜色没有数值"（根因）

不是数据没到 NUI。`qb-hud/client.lua:121-123` 从 `PlayerData.metadata` 读出
`stress / hunger / thirst`，`html/app.js` 的 `hudTick()` 逐字段接住（`:814-816`），
qb-hud 的 html/index.html:235-250 的圆环也绑定了 `:value="hunger"`。

真正的原因是 Quasar 组件的行为：`q-circular-progress` 用了 `show-value`，
**但圆心又放了 `<q-icon>` 子元素** —— 默认插槽一填，`show-value` 的百分比标签就被覆盖。
所以圆环有颜色、有进度，就是没有数字。

顺带两个颜色问题：

| 状态 | 现在的配色 | 问题 |
|---|---|---|
| 饥饿 100 | `#dd6e14`（橙） | 与 31–99 区间**同色**，饱与半饱看起来一样 |
| 饥饿 ≤30 | `#ff0000`（红） | 只在 30 以下突变，没有预警 |
| 口渴 100 / ≤30 | `#1a7cad` / `#ff0000` | 同上 |

### 1.4 数据频率（性能）

`hudTick` 不是每帧发：`client.lua` 里有 `prevPlayerStats` 逐字段比较，只有变化才
`SendNUIMessage`（`:660-675`）。所以这个模块的性能问题**不在状态条**，无需"优化 NUI 频率"。

### 1.5 玩家会卡住的场景（更新）

| # | 场景 | 现在 |
|---|---|---|
| 1 | 快饿死但看不出来 | 圆环只有颜色，31 与 99 同色；无数值 |

### 1.6 CC 调研补充（2026-11-11）

**外部做法**：

| 维度 | 结论 | 来源 |
|---|---|---|
| 形态 | RP 服以**圆环**为主（贴小地图、余光可读）；条形适合精确比较；数字只做辅助。指南强调**别只靠颜色**，要有图标或填充量 | VX-HUD / FR Hub / Sleek / FiveM HUD 设计指南 |
| 隐藏 | 载具数据只在车内；状态只在"变化或偏低"时出现；暂停/电影隐藏。**没找到"战斗时隐藏状态条"的通用规则** | 同上 |
| 低状态 | 共识是**跨阈值提醒一次 + 冷却**，不按 tick 重复；10–20% 是常见临界；建议 3–5 分钟一次。有玩家抱怨每秒重复音效"像坏唱片" | ESX Status Effects / cDev / 设计指南 |

**仓库现状（CC 逐行，含性能）**：

| 问题 | 结论 | 证据 |
|---|---|---|
| 状态来源 | 饥饿/口渴走 `UpdateNeeds`；压力由服务端写 metadata 后 `UpdateStress` 回推；生命/护甲/氧气 native 轮询。**不读写 DB** | `client.lua:633-640, 787-794, 839-841`、`server.lua:68-70` |
| 圆环数值 | **丢在模板层**：`show-value` 被 `<q-icon>` 默认插槽覆盖（与我的结论一致） | `index.html:232/241/250/259/268` |
| 金钱 | 已符合 PO 要求：`updatemoney` 只显示变动账户 2 秒、金额 1 秒 | `client.lua:971-998`、`app.js:641-715` |
| **性能/重复发送** | 路点 500ms 无 diff 重发；罗盘 100ms 轮询、车内 `update`+`baseplate` 双发；未登录重复 `hudtick false`；**电影模式 `Wait(0)` 每帧双发**；车内 `hudtick`+`car` 都带 speed（约 10 条/秒） | `client.lua:1288-1297, 1215-1248, 939-943, 1139-1153` |
| **压力刷屏** | 服务端每收一次 `GainStress` 就 Notify，而客户端射击按 10% 概率发 —— 扣一次扳机可弹多条 | `server.lua:70`、`client.lua:1042-1058` |
| 低状态 | 我这一版的 stress 方向写反了（按"低值"提醒），且没覆盖护甲 | `client.lua:114-153` |

**CC 的分档建议**（与本模块一致，补两条）：

| 档 | 补的条目 |
|---|---|
| `toast` | 油量 ≤20（进车首次 + 每 3 分钟，替代现在的每分钟 error）；压力 **≥80**；护甲 =0 一次 |
| `error` | 饥饿/口渴 **=0 且开始掉血**；压力 =100 黑屏/踉跄；HUD 重载失败 |

**为什么状态不该用通知表达**（CC 的表述比我的准）：HUD 是**连续量**，通知是**离散事件**。
用通知表达状态只有两种结果 —— 按 tick 发（刷屏）或偶尔发（信息过期）。
圆环常驻、余光可读，颜色 + 填充 + 数字三重编码；通知打断、遮挡、有时效，
重复还会让玩家对真正紧急的 error 脱敏。

## 2. 设计（目标）

> 一句总纲：**状态用 HUD 表达，事件才用通知**。HUD 是"一直看得见"的，
> 通知是"打断你一下"的 —— 把状态做成通知（或反过来）都会出错。

### 2.1 圆环：图标在圆心，数值在下方

| 项 | 决策 | 理由 |
|---|---|---|
| 数值 | 圆环下方 10px 小字，`tabular-nums`（数字不跳动） | 圆心留给图标；Quasar 的 `show-value` 会被插槽覆盖 |
| 配色 | 正常 → 正常色；**< 40** → 琥珀；**< 20** → 红 + 脉冲 | 现在只有"≥30 全橙 / <30 红"两档，没有预警区 |
| 隐藏逻辑 | 保持 `dynamic*` 开关（满值时隐藏） | 满状态不占屏幕，是这套 HUD 的好设计，不动 |

### 2.2 压力是"越高越糟"（方向与饥饿/口渴相反）

| 状态 | 提醒阈值 | 重新上膛 | 说明 |
|---|---|---|---|
| 饥饿 / 口渴 | ≤ 20 | ≥ 30 | 越低越糟 |
| **压力** | **≥ 80** | **≤ 30** | 越高越糟，100 会黑屏/踉跄 |
| 护甲 | = 0（一次） | ≥ 20 | 低于 20 不打扰 |

> 这一条是补出来的：第一版把压力也按"低值"提醒，等于平静时提醒、高压时不提醒。

### 2.3 低状态提醒：一次是真的，两次是骚扰

| 项 | 值 | 理由 |
|---|---|---|
| 阈值 | 20 | 低于 20 才开始掉血/掉体力，值得打断 |
| 冷却 | 5 分钟/状态 | 玩家在跑路，不该每 5 秒被提醒 |
| 重新上膛 | 回升到 **30** 才允许再次提醒 | 只在 20 上下抖动时不会反复触发（滞回） |
| 通道 | `toast` | 需要停一下看一眼，不是错误 |

### 2.4 金钱：只在变化时出现（不动）

PO 明确要求保持原样。这条写进闸门，防止以后有人"顺手"改成常显：
qb-hud 的 html/index.html 里的 #money-change 是变化时元素，`#money-cash` 受 `v-if` 控制。

### 2.5 不做的事

| 项 | 理由 |
|---|---|
| 重做 HUD 布局（换形状/换位置） | 当前布局是 PO 已接受的，只补信息不换风格 |
| 加"体力/耐力"等新状态 | 需要玩法侧先定义数据源，本模块只呈现已有数据 |
| 给状态条加音效 | 状态是持续的，音效应该留给事件 |
