## 1. 调研（现状）

| `qb-hud` | 14 | 0 | 6 |
| `qb-scoreboard` | 2 | 0 | 3 |

### 1.2 玩家会卡住的场景

| # | 场景 | 现在 |
|---|---|---|
| 1 | 看余额 | 钱**只在变化时**闪一下（PO 明确要求保持这样），常驻余额不可见 |
| 2 | 看饥渴 | 四个圆环只有颜色，没有数值；快饿死和刚吃饱看着差不多 |
| 3 | 战斗中被通知切断视野 | 中央 toast 2.5 秒，压在准星上方 |

### 1.3 为什么"只有颜色没有数值"（根因）

不是数据没到 NUI。`qb-hud/client.lua:121-123` 从 `PlayerData.metadata` 读出
`stress / hunger / thirst`，`html/app.js` 的 `hudTick()` 逐字段接住（`:814-816`），
qb-hud 的 html/index.html:235-250 的圆环也绑定了 `:value="hunger"`。

真正的原因是 Quasar 组件的行为：`q-circular-progress` 用了 `show-value`，
**但圆心又放了 `<q-icon>` 子元素** —— 默认插槽一填，`show-value` 的百分比标签就被覆盖。
所以圆环有颜色、有进度，就是没有数字。

顺带两个颜色问题：

| 状态 | 现在的配色 | 问题 |
|---|---|---|
| 饥饿 100 | `#dd6e14`（橙） | 与 31–99 区间**同色**，饱与半饱看起来一样 |
| 饥饿 ≤30 | `#ff0000`（红） | 只在 30 以下突变，没有预警 |
| 口渴 100 / ≤30 | `#1a7cad` / `#ff0000` | 同上 |

### 1.4 数据频率（性能）

`hudTick` 不是每帧发：`client.lua` 里有 `prevPlayerStats` 逐字段比较，只有变化才
`SendNUIMessage`（`:660-675`）。所以这个模块的性能问题**不在状态条**，无需"优化 NUI 频率"。

### 1.5 玩家会卡住的场景（更新）

| # | 场景 | 现在 |
|---|---|---|
| 1 | 快饿死但看不出来 | 圆环只有颜色，31 与 99 同色；无数值 |
| 2 | 低状态没有任何提醒 | 靠玩家自己盯圆环 |
| 3 | 看余额 | 钱**只在变化时**闪一下（PO 明确要求保持，不动） |
| 4 | 战斗中被通知切断视野 | 中央 toast 压准星上方（已由 notify 模块定为 2.5s / 最多 2 条） |

## 2. 设计（目标）

> 一句总纲：**状态用 HUD 表达，事件才用通知**。HUD 是"一直看得见"的，
> 通知是"打断你一下"的 —— 把状态做成通知（或反过来）都会出错。

### 2.1 圆环：图标在圆心，数值在下方

| 项 | 决策 | 理由 |
|---|---|---|
| 数值 | 圆环下方 10px 小字，`tabular-nums`（数字不跳动） | 圆心留给图标；Quasar 的 `show-value` 会被插槽覆盖 |
| 配色 | 正常 → 正常色；**< 40** → 琥珀；**< 20** → 红 + 脉冲 | 现在只有"≥30 全橙 / <30 红"两档，没有预警区 |
| 隐藏逻辑 | 保持 `dynamic*` 开关（满值时隐藏） | 满状态不占屏幕，是这套 HUD 的好设计，不动 |

### 2.2 低状态提醒：一次是真的，两次是骚扰

| 项 | 值 | 理由 |
|---|---|---|
| 阈值 | 20 | 低于 20 才开始掉血/掉体力，值得打断 |
| 冷却 | 5 分钟/状态 | 玩家在跑路，不该每 5 秒被提醒 |
| 重新上膛 | 回升到 **30** 才允许再次提醒 | 只在 20 上下抖动时不会反复触发（滞回） |
| 通道 | `toast` | 需要停一下看一眼，不是错误 |

### 2.3 金钱：只在变化时出现（不动）

PO 明确要求保持原样。这条写进闸门，防止以后有人"顺手"改成常显：
qb-hud 的 html/index.html 里的 #money-change 是变化时元素，`#money-cash` 受 `v-if` 控制。

### 2.4 不做的事

| 项 | 理由 |
|---|---|
| 重做 HUD 布局（换形状/换位置） | 当前布局是 PO 已接受的，只补信息不换风格 |
| 加"体力/耐力"等新状态 | 需要玩法侧先定义数据源，本模块只呈现已有数据 |
| 给状态条加音效 | 状态是持续的，音效应该留给事件 |
