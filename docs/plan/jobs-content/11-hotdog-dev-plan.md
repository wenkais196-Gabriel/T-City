## 2. 各片细节

### S0 地图踏勘（0.5 天）

**做什么**：`quest_map.py --coords` 渲染候选点；确定 7 个坐标 + 队列点；写进配置。

**产出**：

| 文件 | 作用 |
|---|---|
| `quest_hotdog.lua`（新配置，走 `quest_registry` 白名单） | 模板定义：租赁点、摆位候选、归还区、顾客生成点、计量参数 |
| `docs/engineering/QUEST_COORDS.md` | 追加热狗线的坐标清单与踏勘截图说明 |

**验收**：`quest_map.py --scan` 对这条线 0 硬错误；每个点离路面 ≤ 30 m、高差 ≤ 5 m（摆位点要能站人，不只是「离路近」）。

### S1 `rental` 原语（2 天）

**服务端会话**（内存 + 事件日志，不落表）：

```
{ citizenid, questId, nodeId, startedAt, deposit, ratePerMin, graceSec, maxMinutes, state }
```

**契约**：

| 事件/入口 | 行为 | 不变量 |
|---|---|---|
| `rental_open`（由 validator 触发） | 校验在租赁点半径内 / 银行余额 ≥ 押金 / 没有未关闭会话 → 扣款 → 写会话 → 写 `quest_event_log` | 同一玩家同一任务只能一个会话；扣款失败则整个动作失败（不允许「半开」） |
| 到期提醒（T-15/T-5/T-1） | 客户端定时器 + 服务端兜底检查 | 提醒不写库 |
| 超时 / 放弃 / 断线 | 关会话 → 按已用分钟计租 → 退押金余款 → 写 `rental_close` | 关会话幂等（重复关闭不重复退钱） |
| 启动扫描 | 查 `rental_open` 无对应 `rental_close` → 标记待退（内存 + 日志） | 不在启动时给离线玩家写钱 |
| 玩家登录 | 有待退记录 → `Player.Functions.AddMoney('bank', 余款)` → 清标记 | 补退只发生一次 |

**测试**（离线，Lua 探针真跑源码）：

1. 余额不足 → 不建会话、不扣钱
2. 重复 open → 第二次被拒（`already_open`）
3. 正常 close → 押金 − 租金 = 退款额
4. 重复 close → 不重复退钱
5. 超时 close → 按 `maxMinutes` 计（不按实时，防止「不还车反而退更多」）
6. 断线 close → 与超时同路径
7. 启动扫描只标记不转账
8. 登录补退只发生一次

**预算影响**：`db_call_sites` +2（写 open / 写 close，都在 `quest_db` owner 内）；无新表；无新 net event（复用 `nodeComplete` + 既有校验器通道）。

### S2 摊位实体（2 天）

**做什么**：`CreateObject('prop_hotdogstand_01')` → 冻结 → `qb-target` 挂交互 → 抓取（`AttachEntityToEntity` + 推车动画）→ 摆放预览（红/绿 + 原因）→ 放下成摊位。

**摆放校验（服务端权威，客户端只画预览）**：

| 判据 | 拒绝原因（玩家可见） |
|---|---|
| 距离租赁点 > 200 m | 「离租赁点太远」 |
| 在车道/路口（路面节点判定） | 「挡在车道上，换个位置」 |
| 距其他摊位 < 15 m | 「旁边已经有摊位」 |
| 斜坡 / 水面 / 室内 | 「这里放不稳」 |
| 与配置的禁摆区相交 | 「这里不许摆摊」 |

**测试**：五种拒绝各一条 + 「合法位置一次成功」；探针真跑摆放判定函数（纯函数，输入坐标 + 环境，输出 ok/reason）。

**实体生命周期**：走 `QuestEntityRegistry`（已有），登记 `on_leave` 回收；断线/放弃/超时都要删实体（在 S1 的会话关闭路径里挂）。

### S3 `minigame` 原语（1.5 天）

**契约**：服务端发 `nonce` + 过期（30 s）；客户端跑 `KeyMinigame(10)`；只回 `{nonce, quit, faults}`；服务端映射：

| faults | 品质 | 物品 |
|---|---|---|
| 0 | exotic | `hotdog_exotic` |
| 1 | rare | `hotdog_rare` |
| ≥2 | common | `hotdog_common` |

**物品**：`qb-core` 的共享物品表新增三条（配置平面，不改逻辑），重量/图沿用 `sandwich` 风格。

**原料**：v1 抽象库存（推车自带 30 份），不物品化（Q9）；做一份扣一份，`原料 0` 时拒绝并提示。

**幂等**：同一 nonce 只能用一次；重复上报返回 `already_used` 且不产出。

**测试**：faults 三档映射 / `quit=true` 不产出且不扣原料 / nonce 重复 / nonce 过期 / 非法 faults（负数、>10）/ 原料 0 / 冷却。

### S4 `vendor_session`（2.5 天）

**NPC 顾客**：

| 项 | 值（配置，非定值） |
|---|---|
| 并发 | 每摊 1 位、每玩家 1 位、**全局 8**（独立预算，不复用 police 的 6 槽） |
| 首个顾客 | 开卖后 8–15 s |
| 后续间隔 | 15–40 s；上一位离开后 ≥ 8 s |
| 耐心 | 45 s 总上限；摊主做热狗时冻结 |
| 连续拒绝 | 3 次 → 60 s 不再生成 |

**成交校验（服务端三件套 + 幂等）**：距离 ≤ 4 m、库存足够、金额由服务端算（不信客户端报价）、`offerId` 一次性。

**玩家购买**：`qb-target` 菜单（每档一行 + 库存 + 单价），服务端串行扣库存；三种不可买状态（打烊/售罄/摊主不在）都要有字（A10）。

**测试**：距离超限 / 库存不足 / 重复 `offerId` / 玩家购买竞态（两人同时买最后一份）/ 预算上限（第 9 个顾客被拒）/ 拒绝 3 次触发冷却。

**预算影响**：广播点 0（全部单点事件）；`warm_polling_loops` 不新增（用 `SetTimeout` 链）；NPC 预算新增一个独立计数器（不碰 police 的）。

### S5 `settle`（1.5 天）

**账单六类**（A6/A19）：押金、租金、售出现金、成品回收、原料回收、税（无税率则显示「0%（未启用）」并灰掉）→ 净额。

**不变量**：分项之和 = 净额；售出标「已付现」不进净额；重复结算返回上一张回执（幂等）；关闭后可回看（内存保留最近 5 张）。

**测试**：账单算式（纯函数，喂 6 组数字）/ 重复结算 / 关闭后回看 / 负数净额（押金不足时按 Q20 在配置加载期就拒绝上线）。

### S6 UX 收口（2 天）

- 状态条：`custom-prompt.SetContext` 六项（成品/原料/顾客/已售/押金/剩余时间）
- 文案：按规格 §6 的中英双语表落地，占位符参数化
- 音效：按规格 §7 的清单（10 个 ogg 全部已存在，已核对）
- 手机任务：阶段文案映射（A21）
- **旧壳 `hotdog_vendor` 下线**（Q22）：新线真机验收通过后，把旧壳从注册表移除，CHANGELOG 写明「旧壳退役」

## 3. 每片的完成定义（DoD）

一片算完成，必须同时满足：

1. 代码 + 配置 + 测试在一个 PR 里；测试含**反向校验**（坏形状必须红）；
2. 全量 `pytest tests/unit tests/architecture` 绿；Lua 改动过 `luac5.4 -p`；
3. 新 net event 已登记并鉴权；`db_call_sites` 增量在 PR body 里写明并给理由；
4. UX 侧对应的 A# 项在真机走过一次，结果写进本片的验收记录（哪条过、哪条没过、为什么）；
5. CHANGELOG 有一行；文档若新增要 `docs_lifecycle --index`。

## 4. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 推车是 prop，容易被撞飞/卡住 | A13 说不清「车被摧毁」 | 按 Q15 定义为「实体丢失/掉水/出界」，不做血量；S2 里就挂上「丢失 → FORCED 收摊」 |
| NPC 顾客与玩家顾客并发扣库存 | 超卖 | 服务端串行扣减 + `offerId` 幂等；S4 专门测竞态 |
| 账单用菜单渲染可能不够漂亮 | A6 观感 | 先用菜单证明「信息齐全」，观感问题单独记一条，不阻塞 |
| 押金补退发生在登录时 | 玩家可能以为钱丢了 | 状态条与租赁点提示「有待退押金 $X」，A12 里加一条 |
| 旧壳下线影响既有玩家 | 收益断层 | 新线真机通过后再下线，且先跑一周并行只读观察（不双发钱） |
