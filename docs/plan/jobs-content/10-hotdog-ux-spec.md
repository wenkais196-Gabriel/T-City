# 热狗摊玩家 UX 规格

> 状态：草稿。本文件只写玩家可见的规格，不含实现代码、不调数值。
> 四个原语（rental / minigame / vendor_session / settle）的样板职业。

## 0. 文档说明与问题索引

### 0.1 这份文档是什么

这是「热狗摊」职业循环的**玩家体验规格**，也是四个原语（rental / minigame /
vendor_session / settle）的第一份样板规格。它回答三件事：

1. 玩家在每个时刻**看到、听到、能做什么**；
2. 每个失败分支**对玩家说哪句人话**，以及怎么继续；
3. 验收的人**怎么打勾**，开发的哪些部分能离线测、哪些必须真机。

**不包含**：Lua / JS 实现、配置字段、数值调参、数据库结构、网络事件定义。
文中的金额、分钟数、库存数只用于**展示格式**，不是定值；数值一轮统一另算。
第一版也不做声望/等级成长、自由定价、物品化原料——它们会影响后续平衡，见 §11。

### 0.5 术语

| 术语 | 含义 |
|---|---|
| 租赁点 | 玩家租推车、还推车、看账单的固定地点 |
| 推车 | 可推的摊位道具；放下后成为摊位 |
| 摊位 | 已放下的经营实体；有营业/打烊两种状态 |
| 原料 | 尚未制作的食材包；做一份消耗一份 |
| 成品 | 已做好的热狗，分普通 / 稀有 / 异域三档 |
| 摊主 | 当前租借会话的拥有者，只有他能管理摊位 |
| 顾客 | NPC 顾客；由服务端生成、客户端驱动走位 |
| 玩家顾客 | 其他玩家，通过摊位 target 购买 |
| 会话 | 一次「租 → 还」的完整租借记录；押金、租金、账单都挂在会话上 |

## 1. 一句话目标与 30 秒概要

### 1.1 一句话目标

让玩家在 **30 秒内理解「租—推—摆—做—卖—还」的大致循环，并在 60 秒内完成第一笔成交**，
且在每一次成交和结算时都能看懂：钱从哪里来、到哪里去、下一句该按什么。

### 1.2 玩家视角的 30 秒

> 你在 Legion Square 附近看到一个热狗图标。走过去，3D 文字写着「热狗推车租赁」。
> 按 E，菜单告诉你：押金 $250 从银行扣，租金按分钟算，归还时退押金。
> 确认后，一辆推车出现在你面前，车铃响了一声。你按 E 抓住车，把它推到广场边的
> 绿框里，按 G 放下——地面先变绿，放下后提示「按 G 开卖」。
> 开卖后，你按 E 在烤架上做第一份热狗：10 次按键小游戏，0 次失误，toast 弹出
> 「★ 完美！异域热狗 ×1」。一位顾客从街角走来，头顶出现「顾客 · 等待点单」。
> 你按 E 接待，报价面板弹出：「普通热狗 ×2 · $10 · 顾客耐心 12 秒」。
> 按 Y 成交，手递手动画，左下角跳出「售出 普通热狗 ×2 · +$10 现金」。
> 你可以继续做、继续卖；打烊时按 G，把车推回租赁点，在归还区按 G 放下并结算。
> 账单逐行列：售出流水、押金、租金、成品回收、原料回收、税，最后是退回银行的钱和本班合计。

### 1.3 30 秒节奏表

| 时间 | 玩家在做什么 | 玩家应该已经理解 | 对应验收 |
|---|---|---|---|
| 0–5 s | 看到 blip / 3D 文字，按 E 打开租赁菜单 | 这是租的，不是买的；押金会退 | A1、A2 |
| 5–15 s | 抓住推车，推到绿框，放下 | 推车要自己推；绿框才是合法摊位 | A5、A11 |
| 15–25 s | 按 G 开卖，按 E 做第一份热狗 | 做热狗是小游戏；品质三档 | A8、A9 |
| 25–35 s | 顾客走近，按 E 接待，按 Y 成交 | 成交有报价、有耐心、现金立刻到账 | A7、A8 |
| 35–50 s | 继续做/卖；玩家顾客通过 ALT 购买 | 做和卖可以并行；玩家也能买 | A7、A10 |
| 50–60 s | 按 G 打烊，推回租赁点，在归还区按 G 放下并结算 | 账单逐行可对账；押金退回银行 | A3、A6、A19 |

### 1.4 三条设计支柱

| 支柱 | 含义 | 对其他职业的可复用性 |
|---|---|---|
| **每个动作都有回路** | 按 E 之后一定有一个可见结果：提示、动画、菜单、通知或账单行；不允许“按了没反应” | 所有生产-售卖型职业 |
| **服务端算钱，客户端演钱** | 玩家看到的所有数字都来自服务端；客户端只负责把数字演得好看 | rental / vendor_session / settle |
| **经营是连续的，不是跑点** | 快乐来自“做—卖—收”的循环，所以 HUD、报价、结算必须常驻可读 | hotdog / 矿工 / 洗衣 / 渔夫 |

## 2. 状态机

> 这条循环不是一条直线：外层是「租 → 还」的会话，内层是「做」与「卖」两条可以同时存在的线。
> 所以状态机拆成 **1 个生命周期 + 3 个正交子状态**，而不是一张 20 个节点的大图。
>
> §2.3 是状态索引表；每条转换的**玩家理由**和**验收**在 §2.5（并行/互斥）、§2.6（不变量）、
> §2.7（异常）以及 §3 的对应状态卡里，不在这张索引表里重复。

### 2.1 四个维度

| 维度 | 含义 | 取值 | 谁来改 |
|---|---|---|---|
| **L 生命周期** | 一次租借会话走到哪一步 | IDLE / RENT_MENU / CART_FREE / PUSHING / PLACING / DEPLOYED / PACKING / RETURN_MENU / SETTLING / SETTLED / SUSPENDED / FORCED | 服务端会话 + 玩家交互 |
| **B 营业** | 摊位是否在接客 | CLOSED / OPEN | 玩家按 G；死亡/断线/售罄会自动落回 CLOSED |
| **A 摊主动作** | 摊主的手在干什么 | IDLE / COOKING / SERVING | 玩家按 E；NUI 小游戏/成交动画期间锁定 |
| **C 顾客** | NPC 顾客走到哪一步 | NONE / INBOUND / WAITING / QUOTE | 服务端排班 + 客户端的走位回调 |
| **P 玩家顾客** | 其他玩家的购买流程 | 每个玩家独立：NONE / BROWSING / BUYING | 玩家自己点 target |

> **P 不在摊主的状态机里**。十个玩家同时看菜单，不会让摊主进入十个状态；
> 服务端只按「库存是否够、摊位是否营业、距离是否合法」逐笔裁决。

> `SUSPENDED` 记录断线前的 L（`resumeState`）：它覆盖 DEPLOYED / PUSHING / PLACING / CART_FREE，
> 重连后回到原 L；它不是一个独立的经营阶段。超过宽限期则走 FORCED。

### 2.3 生命周期状态表

| L 状态 | 中文名 | 进入条件 | 离开条件 | 可并行子状态 | 玩家看到什么 |
|---|---|---|---|---|---|
| IDLE | 未接单 | 没有会话；或账单已关闭 | 在租赁点按 E | 无 | 租赁点常驻 3D 文字 / blip；没有摊位 HUD |
| RENT_MENU | 租赁确认 | 从 IDLE 按 E，服务端已算出报价 | 确认 → CART_FREE；取消/Esc → IDLE；被拒 → 留在本状态并显示原因 | 无 | qb-menu 面板：押金、租金、原料、上限、预计时长 |
| CART_FREE | 推车可抓 | 押金扣款成功并生成推车；或从 PUSHING 放下后取消摆放；或死亡后推车脱手 | 在推车旁按 E → PUSHING；**首次生成后** 5 分钟不抓 → 自动取消并全退（已抓过/摆过不适用） | 无 | 推车实体、头顶 3D 文字、主提示「E 抓住推车」 |
| PUSHING | 推车中 | 在 CART_FREE 按 E 抓住 | 普通地面按 G → PLACING；归还区按 G → RETURN_MENU；推车丢失/被毁 → FORCED | 无（推车时不能做/卖） | 推车跟随、屏幕下方提示、到归还区时提示变化 |
| PLACING | 摆放预览 | 从 PUSHING 按 G | 确认且服务端通过 → DEPLOYED；取消/推走 → CART_FREE；60 秒无操作 → CART_FREE | 无 | 地面绿/红框、推车幽灵、具体原因、主提示 |
| DEPLOYED | 已摆摊 | 摆放通过 | 打烊后按 E → PACKING；超时/断线过期/推车丢失 → FORCED | B / A / C / P 四维全部可动 | 摊位 HUD、营业状态、成品/原料、顾客、剩余时间 |
| PACKING | 收摊动画 | 在 DEPLOYED 且 B=CLOSED、A=IDLE、C=NONE 时按 E | 1.5 秒后自动 → PUSHING | 无 | 收摊动画、推车重新出现、提示「推回租赁点」 |
| RETURN_MENU | 归还确认 | 在归还区把推车放下（G） | 确认 → SETTLING；取消 → PUSHING；被拒 → 留在本状态并显示原因 | 无 | 归还菜单：计费分钟、预计净额、回收规则 |
| SETTLING | 结算中 | 归还确认；或 FORCED 自动进入 | 成功 → SETTLED；失败 → RETURN_MENU / 重试提示 | 无 | 短暂 loading（≤ 1 s），按钮防连点 |
| SETTLED | 已结算 | 服务端结算成功 | 关闭账单 → IDLE | 无 | 结算回执面板（待建），可回看 |
| SUSPENDED | 掉线挂起 | 玩家断线且会话未结算 | 宽限期内重连 → 回到原 L；超时 → FORCED | B 强制 CLOSED，C 清空，A 取消 | 重连后 toast + 摊位 HUD 显示「挂起恢复」 |
| FORCED | 强制收摊 | 超时、断线过期、推车丢失/被毁、服务器重启、职业变更 | 自动 SETTLING → SETTLED | 全部清空 | error/toast 说明原因；下次登录显示账单 |

### 2.4 营业子状态（B）与动作子状态（A）

| 子状态 | 进入条件 | 离开条件 | 玩家看到什么 | 失败/边界 |
|---|---|---|---|---|
| B=CLOSED | 初始；按 G 打烊；死亡/断线/售罄自动进入 | 按 G 开卖（需成品 > 0、A=IDLE、C=NONE） | HUD 显示「已打烊」；主提示「G 开卖」；玩家 target 显示「打烊中」 | 成品为 0 时按 G：error「还没有成品，先按 E 做几份」 |
| B=OPEN | 按 G 开卖通过 | 按 G 打烊；售罄自动打烊；死亡/断线强制打烊 | HUD 显示「营业中」；玩家 target 可购买；NPC 开始排班 | 顾客在等待/报价时按 G：提示「先处理顾客」；做热狗时按 G：提示「做完这一份再打烊」 |
| A=IDLE | 默认；做完/成交结束 | 按 E 做热狗 → COOKING；按 E 接待 → SERVING（经报价） | 主提示随上下文变化 | 无 |
| A=COOKING | 按 E 且原料 > 0、成品未满、C≠QUOTE | 小游戏结束/取消 → IDLE | qb-minigames 的 KeyMinigame 面板；面板外仍有摊位 HUD | 原料为 0 → COOK-07；成品满 → COOK-08；Esc 退出 = 取消，不扣原料 |
| A=SERVING | 报价面板按 Y 且服务端扣库存成功 | 1.5 秒手递手动画结束 → IDLE | 成交动画、+$ toast、库存 −N | 库存被玩家顾客抢先买走 → CUST-14；顾客离开动画照常播 |
| C=NONE | 初始；顾客离开/成交/超时 | 服务端排班到点 → INBOUND | 无 | 无 |
| C=INBOUND | 服务端排班，客户端生成临时 ped | 走到队列点 → WAITING；20 秒没走到 → 消失并回 NONE | 顾客从街角走来；头顶小图标；feed「有顾客来了」 | 被车撞/卡住 → 超时消失，玩家不扣钱；不占 police 预算，用 custom-quest 独立预算 |
| C=WAITING | 顾客到达队列点 | 玩家按 E → QUOTE；耐心耗尽 → 离开；B 关闭 → 离开 | 3D 文字「顾客 · 等待点单」；主提示「E 接待顾客」；报价倒计时只在摊主可接待时走，但总等待上限 45 秒 | 顾客被无视 → 15 秒后离开，feed 说明；连续拒绝有短冷却 |

### 2.8 与现有 quest 引擎 / 预算闸的接缝

| 事项 | 现状（来自仓库） | 本线怎么做 | 验收 |
|---|---|---|---|
| 步骤类型 | `Config.Quest.StepTypes` 声明 13 种；`combat` / `wait` / `placement` 当前已有客户端/服务端分支，但成熟度不一（07 曾把其中几种标为死类型，代码后来补过） | 本线**不依赖**这些有争议的类型；`rental` / `minigame` / `vendor_session` / `settle` 是**本线要新增**的原语，不在现有 13 种里 | D2、D7 |
| 主步骤结构 | 引擎是线性 FSM，只能表达外层 | 主步骤只有 `rental → vendor_session → settle` 三步；`minigame` 是 vendor_session 内的**可重复子动作**（对应 07 的 `repeatable`），不推进主步骤；做热狗不单独占一条任务 | D2、D7 |
| 会话键 | 多站校验器用 `citizenid:questId` 作为内存会话键 | 租借会话沿用同一形状；不要另造一套用户 ID 拼接 | D2、D6 |
| 错误码 | 校验器返回 `too_far` / `out_of_order` / `wrong_job` 等机器码 | 服务端错误码 → §6 的玩家文案；客户端只渲染文案，不显示机器码 | A4、D4 |
| NPC 预算 | police 的 `NPCBudget` 是全局 6 槽 / 每人 2 槽 / TTL 10 分钟，属于 police 域 | **不复用**；custom-quest 内独立预算：1 槽/玩家、全局上限 8、TTL 5 分钟；形状参照 FIT-07 的「shared 纯函数 + server 内存表 + sweep」 | A18、D10 |
| 循环预算 | io_budget 预算表：warm ≤ 5、fast ≤ 2、wait_zero ≤ 1 | 顾客排班用 `SetTimeout` 链，不新增 `while true … Wait(1000)`；HUD 只在状态变化时推 | D10、A17 |
| 3D 文字预算 | `DrawText3D` ≤ 4 个调用点 | 全场景只保留**一个** 3D 文字绘制点，由最近锚点决定内容；复用 CFShared.DrawText3D | A1、A17 |
| DB 预算 | `db_call_sites` 已 465，租借/账单建议不落库 | 每笔成交、每次小游戏**不写库**；只在 Q4 决定的最小会话日志上写开始/关闭两条 | D12、Q4 |

> 这张表是“别把 UX 规格写成实现规格”的边界：上面只约束**不能违反的现有事实**，
> 具体函数名、字段名、事件名不在本文定义。验收时按这张表检查有没有偷偷新增轮询/广播/DB 写。

### 3.11 掉线、超时与强制收摊（L=SUSPENDED / FORCED）

| 维度 | 规格 | 理由 | 验收 |
|---|---|---|---|
| 看到 · 世界 3D | 掉线时摊位/推车留在原地；其他玩家看到「摊主离开 · 暂停营业」/「Vendor away · Paused」；摊主重连后看到「摊位已恢复」 | 世界不能因为一个人掉线就“摊位消失” | A12 |
| 看到 · 主提示 | 重连后：`E 继续摊位`；推车在归还区时 `G 放下并结算`；超时后：`E 查看待结算账单`（关闭后 `ALT 查看上次账单`） | 重连第一屏就要告诉玩家“发生了什么、下一步按什么” | A12、A13 |
| 看到 · 屏幕浮层 | 重连 toast：「你有一个未结算的热狗摊。推车还在原地，10 分钟内回去处理」；状态条：「挂起恢复 · 剩余宽限 8:42 · 押金 $250 托管中」；超时 toast：「已超时，摊位自动收回，账单已生成」 | 押金状态必须在重连后第一眼可见 | A12、A13 |
| 看到 · blip / 任务列表 | 摊位/推车 blip 保持；手机任务：「摊位挂起，回去处理」 | 玩家能找回自己的摊 | A12 |
| 听到 | 重连：`BellStartEnd`（本地，0.3）；超时：`Alert`（本地，0.35）；强制结算完成：`Shop`（0.25） | 重连和超时是两种情绪，声音要区分 | A5 |
| 能做 | 重连后回到摊位继续/结算；宽限期内不额外扣钱；超时后只能看账单 | 给玩家补救窗口，但不允许无限挂机 | A12、A13 |
| 失败态 | 宽限期满：FORCED，error「摊位已自动结算，押金扣除租金后已退回」；服务器重启：toast「服务器重启，摊位已收回」+ 账单；押金退款异常：error「押金退款失败，请联系管理员」+ 账单编号 | 最坏情况下也要给一个可查询的编号，不能只打日志 | A4、A12 |

> **押金可见性贯穿所有状态**：租赁确认时显示“将扣多少”，推车/摆摊/营业时状态条显示“托管中”，
> 结算时账单显示“退多少”，重连时第一屏显示“还在不在”。任何一屏都不允许押金“隐身”。
> 验收 A3、A12、A19。

### 3.12 任务列表与阶段文案映射

手机任务 App 的「进行中」只保留**一条**热狗条目，阶段文案按下表更新；不要每个动作都新增一条。

| L / 子状态 | 手机任务条目（中） | 手机任务条目（英） | HUD 阶段 | 验收 |
|---|---|---|---|---|
| 未接取 | 热狗摊贩 · 可接取 | Hotdog Vendor · Available | 无 HUD | A21 |
| RENT_MENU / CART_FREE / PUSHING / PLACING | 热狗摊贩 · 租推车并推到摊位 | Hotdog Vendor · Rent a cart and push it to a pitch | 推车中 / 摆放预览 | A2、A21 |

| PACKING / PUSHING 返回 / RETURN_MENU | 热狗摊贩 · 把推车推回租赁点 | Hotdog Vendor · Push the cart back | 收摊中 | A2、A21 |

规则：

| 规则 | 理由 | 验收 |
|---|---|---|
| 同一时间只有一条进行中条目；阶段变化用“更新”而不是“新增” | 手机上堆 8 条同名任务会让玩家不知道看哪条 | A21 |

| 阶段文案要能在阶段变化时刷新 | 如果手机 App 只读 DB 的 `current_step`，阶段变化就必须同步更新它，或提供一条轻量刷新；否则 A21 会失败 | A21、D7 |
| 不显示内部状态码（`DEPLOYED` 等） | 玩家不需要看实现 | A15 |

## 6. 文案表（中英双语）

> 逐条文案的验收统一为 **A15（中英完整、长度不截断）** 加上该组对应的行为验收。
> 每组的**措辞理由**写在该组表后的引用块里；不要只改字面而不改行为验收。

### 6.1 语气与格式规则

| 规则 | 说明 | 理由 | 验收 |
|---|---|---|---|
| 先说原因，再说动作 | 例：「成品放不下了，先卖一些」而不是「操作失败」 | 玩家要知道“为什么”和“下一步” | A4 |
| 一句话只说一件事 | 主提示 ≤ 28 个汉字 / 60 个英文字符；通知正文 ≤ 60 汉字 / 120 字符 | 屏幕空间有限，长句会被截断 | A15 |
| 用「你」，不用「您」 | 和现有任务文案保持一致 | 语气统一，不像客服工单 | A15 |
| 金额统一 `$1,234` | 千分位；不显示小数，除非税额产生小数 | 玩家用计算器能对上 | A19 |
| 时间统一 `mm:ss` 或 `X 分钟` | 剩余时间用 `mm:ss`；计费用「X 分钟」 | 两种时间语义不能混 | A19 |
| 不在文案里写内部码 | 不出现 `validator_fail_03` 之类 | 玩家不需要看日志 | A4 |
| **数字必须参数注入** | 文案模板只保留格式，`$250`、`42 分钟`、`10 分钟` 都是占位 | 避免改配置后文案漂移 | D1、D3 |
| 中英同时存在 | 中文为主、英文为辅；英文不机翻，按玩家口语改写 | 服务器有英文玩家 | A15 |
| 通知必须有 title + body | custom-notify 的 Push 要求 title 非空：feed 的 title 用短标签（「热狗摊」「顾客」），toast/error 的 title 用状态名（「押金不足」「营业中」）；表中句子作为 body。3D/主提示/菜单/按钮没有 title | 否则通知会被服务端拒绝，玩家什么都看不到 | A4、D4 |
| 接受相同通知合并 | custom-notify 会把 3 秒内完全相同的 title+body 合并成「×N」；高频相同成交可以接受，不要为了防合并往文案里塞随机数 | 合并是特性，不是 bug；塞随机数会让日志和文案都变脏 | A3 |

## 7. 动画与音效清单

> 加一条声音/动画的唯一理由：它对应一个**玩家心理节点**（开始、成功、失败、警告、恢复）。
> 没有对应节点的声音/动画不加；已有节点但可以用现有资源表达的，不新增资源。
> 每条的资源来源与验收在表里；「为什么是这个节点」在各节的 UX 卡里。

### 7.1 音效规则

| 规则 | 说明 | 理由 | 验收 |
|---|---|---|---|
| 一个事件一个声音 | 同一帧不叠加两个声音；成交时 `Shop` 和 `consume` 只选一个 | 叠音会糊，玩家分不清是成交还是报错 | A5 |
| 本地声 vs 世界声 | UI/个人反馈用 `InteractSound_SV:PlayOnSource`；顾客到访、开店铃用 `PlayWithinDistance`（≤ 25 m） | 让附近玩家感知“这里在营业”，但不要全服广播 | A5、D8 |
| 音量上限 0.5 | 高频音（tick、按键）0.2–0.25；成交/开店 0.3–0.35 | 保护玩家耳朵，也避免盖过语音 | A5 |
| 冷却 | 同一声效 100 ms 内不重复（interact-sound 自带限流）；倒计时 `hazard_tick` 每秒最多 1 次，最多 5 次 | 防止连点刷声 | A14 |
| 不新增循环声 | 烤架/推车不做常驻循环；需要氛围时用现有环境音 | 循环声在多人场景会变成噪音 | A17 |
| 失败声要轻 | error 用 `Alert` 0.2–0.3，不用刺耳警报 | 失败已经让人烦，声音不要再补刀 | A4 |

## 8. 账单与数值展示规则

> 这一节只规定**展示什么、怎么对账**，不调数值。为了让示例能对上，全文示例统一采用：
> 押金 $250、租金 $4/分钟、原料 30、成品上限 30、营业 42 分钟、税率 5%。
> 这些数字是**格式样例**；实现时全部从配置注入，文案模板里不写死。
>
> **这个样例故意是一班亏损**：42 分钟只卖出 15 份，租金 $168 盖过售出 $109。
> 账单必须让玩家一眼看出亏在哪；如果样例改成盈利，反而看不出“租金”这一行的重要性。

### 8.1 账单分两块

账单必须分成两块，因为它们的钱流向不同：

```
┌─ A. 经营流水（已现金支付，不再打进本次退款）─────────────┐
│  售出 15 份                                   +$109     │
│    · 异域 2 × $12 = $24                                 │
│    · 稀有 5 × $9  = $45                                 │
│    · 普通 8 × $5  = $40                                 │
└──────────────────────────────────────────────────────────┘
┌─ B. 押金结算（退回银行）─────────────────────────────────┐
│  押金退回（银行）                             +$250     │
│  租金 42 分钟 × $4/分钟                       −$168     │
│  成品回收 4 份                                +$10      │
│    · 稀有 1 × $4 = $4                                  │
│    · 普通 3 × $2 = $6                                  │
│  原料回收 6 份                                +$6       │
│    · 6 × $1 = $6                                       │
│  营业税 5%                                    −$5       │
│  ─────────────────────────────────────────────────────  │
│  本次退回银行                                 +$93      │
└──────────────────────────────────────────────────────────┘
本班净赚：−$48（这一班亏了）
资金回到手里：现金 +$109 · 银行 +$93 · 合计 +$202
```

| 块 | 包含 | 为什么不混在一起 | 验收 |
|---|---|---|---|
| A 经营流水 | 售出（NPC + 玩家） | 每笔成交时已经以现金支付；再算进退款会重复 | A3、A19 |
| B 押金结算 | 押金、租金、成品回收、原料回收、税、其他费用 | 这些才是结算时真正动银行的钱 | A6、A19 |
| 净赚 | 售出 + 回收 − 租金 − 税 − 其他费用 | 押金是玩家自己的钱，不能算成利润；亏了也要让玩家看懂 | A19 |
| 资金回到手里 | 现金售出 + 银行退款 | 玩家想知道“这一班总共拿回多少钱”，必须标清两个账户 | A19 |

### 8.2 每一行的数据来源

| 行 | 来源 | 计算 | 展示规则 | 验收 |
|---|---|---|---|---|
| 押金退回 | 租借会话的 `deposit`；租借确认时从银行扣 | 固定值 | 写「押金退回（银行）」+ `+$250`；若押金来自现金则写「现金」 | A3、A12 |
| 租金 | 会话的 `startedAt`、`returnedAt`、`graceSec`、`ratePerMin`、`maxMinutes` | `计费分钟 = min(maxMinutes, max(0, ceil((已用秒 − graceSec) / 60)))`；`租金 = 计费分钟 × ratePerMin` | 显示「42 分钟 × $4/分钟」；下一行小字显示实际用时「42 分 18 秒」；保护期内显示「前 60 秒不计」 | A19 |
| 售出 | `vendor_session` 的成交流水：`{quality, count, unitPrice, buyerKind, at}` | 按品质分组：`sum(count × unitPrice)` | 先在 A 块显示总额，再按品质列子行；标记「已付现」 | A3、A19 |
| 成品回收 | 会话结束时未售成品：`unsoldByQuality` × 回收价 | `sum(count × recoveryPrice[quality])` | 显示总份数和金额；子行可选显示各档份数 | A6 |
| 原料回收 | 会话结束时未用原料 × 回收价 | `unusedRaw × rawRecoveryPrice` | 显示份数和金额 | A6 |
| 营业税 | 配置的税率与税基（售出总额） | `round(售出总额 × taxRate)` | 显示「营业税 5%」；税率为 0 时显示「营业税 0%（未启用）」灰字 | A19 |
| 推车回收费 | 推车丢失/被毁时由服务端记的一条费用 | 配置固定值或按距离 | 只在发生时出现；没有发生时**不显示**，不写 `$0` | A13 |
| 超时 | 不单独列违约金；超时后租金按 `maxMinutes` 计 | 见租金行 | 租金行写明「按上限 60 分钟计」 | A13、A19 |
| 净额 | 押金 − 租金 + 成品回收 + 原料回收 − 税 − 其他费用 | 整数求和 | 加粗；必须等于 B 块各行之和；不把 A 块算进来 | A19 |
| 本班净赚 | 售出总额 + 成品回收 + 原料回收 − 租金 − 税 − 其他费用 | 不含押金；结果可为负 | 显示正负号；负值时写「这一班亏了 $X」 | A19 |
| 资金回到手里 | A 块现金 + B 块净额 | 现金 + 银行 | 显示两个账户和合计 | A19 |

### 8.3 对账与四舍五入

| 规则 | 说明 | 理由 | 验收 |
|---|---|---|---|
| 金额用整数美元 | 服务端计算也用整数；税额四舍五入到元 | 玩家用计算器能对上，不出现分币级别的漂移 | A19、D3 |
| 先算税，再求和 | 税额四舍五入后再进入净额 | 避免“各行相加差 1 元” | D3 |
| 净额必须等于 B 块之和 | UI 不显示服务端另算的 total，而是把 B 块各行相加 | 防止服务端与 UI 各算一套 | A19、D3 |
| 出现差异时显示「对账差异」行 | 只应在 bug 时出现；同时写审计日志 | 不隐藏差异，也不展示一个假总数 | D3 |
| 押金 ≥ 最大租金 | 配置加载时校验：`deposit >= maxMinutes × ratePerMin` | 保证正常情况下净额不为负 | D3、A19 |
| 负净额的兜底 | 若配置校验被绕过：先从押金扣，再扣银行，最后扣现金；仍不足则记一笔欠款、允许结算，下次登录优先扣除，并在账单显示「需补扣 $X」 | 不让玩家卡在“结算不了也走不了”的状态 | A4、D3 |
| 重复结算 | 同一会话只允许一次成功结算；第二次打开同一张账单 | 防止重复退款 | A20、D6 |

### 8.4 展示规则

| 对象 | 规则 | 示例 | 理由 | 验收 |
|---|---|---|---|---|
| 金额 | `$` + 千分位；整数；负数用 `−` 不用括号 | `+$1,234` / `−$168` | 正负号比颜色可靠 | A16、A19 |
| 时间 | 剩余用 `mm:ss`；计费用「X 分钟」；时间点用 24 小时制 | `32:15` / `42 分钟` / `14:44` | 三种语义不能混 | A19 |
| 数量 | 「份」为单位；品质用中文名 + 符号 | `异域 2 份 ★` | 符号是颜色的替代 | A16 |
| 税率 | 百分比 + 税基说明 | 「营业税 5%（按售出总额）」 | 玩家知道税按什么算 | A19 |
| 预估 | 结算前一律写「预计」 | 「预计退回 $93」 | 结算前不能承诺最终金额 | A6 |
| 账单号 | 短编号，可读、可报给管理员 | `#HD-1042` | 出问题能定位 | A12 |
| 内部信息 | 不显示会话 key、citizenid、错误码、反作弊原因 | 只显示账单号和玩家可读原因 | 保护隐私，也不给刷子提示 | A4 |

| 场景 | 行为 | 理由 | 验收 |

| 结算完成 | 账单面板自动打开；`Esc` / 「关闭」关闭 | 结算是循环的终点，必须看到结果 | A6 |

## 9. 中断与异常处理

> 这一节回答的是：**出事之后，玩家还能不能救、押金还在不在、下一步按什么。**
> 任何一条都不允许只写服务端日志。

### 9.1 断线重连（最重要的一条）

**摊位还在吗？** 在。断线不删除推车/摊位实体，也不关闭会话；但营业状态立刻落回 CLOSED，
顾客离开，正在做的小游戏取消（不扣原料），正在播放的成交动画按服务端结果决定是否完成。

```
玩家断线
  │
  ├─ 会话存在，宽限期内重连 ──► 恢复：摊位/推车原地；B=CLOSED；押金仍托管
  │                              玩家看到：toast + HUD「挂起恢复 · 剩余宽限 8:42」
  │
  ├─ 会话存在，宽限期已过 ────► FORCED：自动收摊、自动结算、生成账单
  │                              下次登录看到：toast + 账单
  │
  └─ 会话不存在（服务器重启/资源重启）► 必须走持久化恢复或退款保证
                                 玩家看到：toast + 账单号（见 §11 Q4）
```

| 时点 | 服务端动作 | 玩家看到 | 理由 | 验收 |
|---|---|---|---|---|
| 断线瞬间 | 会话挂起；B=CLOSED；C 清空；A 取消；押金保持托管；推车/摊位保留 | 其他玩家看到「摊主离开 · 暂停营业」 | 世界不能因为一个人掉线就消失 | A12 |
| 断线时正在推车/摆放 | 推车脱手，停在最后位置；L 回到 CART_FREE；不删除实体 | 重连后 3D「热狗推车 · [E] 抓住」 | 否则推车会跟着离线 ped 一起消失 | A12 |

| 摊主被抢 | 只影响身上的现金；库存、押金、摊位不可抢 | 现金变化走现有抢劫通知；摊位 toast「摊位已自动打烊」 | 街道摊位的风险是现金，不是押金 | A13 |
| 摊主被捕 | B=CLOSED；如果刑期 > 宽限期，服务端在宽限期满后 FORCED | toast「你被捕了，摊位将在 10 分钟后自动结算」 | 坐牢不能成为无限挂机的理由 | A13 |
| 复活后回到摊位 | 按 E 继续；B 仍 CLOSED；按 G 重开 | 3D「已打烊 · [G] 开卖」 | 玩家需要重新开卖，系统不替玩家决定 | A12 |

### 9.4 推车被撞、翻倒、丢失

| 事件 | 服务端动作 | 玩家看到 | 理由 | 验收 |
|---|---|---|---|---|
| 车辆低速碰到推车 | 推车晃一下，不翻 | 轻微音效/动画 | 低速不应惩罚 | A13 |
| 车辆高速撞到推车 | 推车翻倒 3 秒；B=CLOSED；C 离开 | 3D「推车翻了 · [E] 扶正」+ `Alert`；扶正 1.5 秒后可继续 | 撞击要有后果，但玩家能救 | A13 |
| 翻倒时再次被撞 | 少量成品报损（配置值，最多 3 份/会话）；不扣原料 | feed「1 份热狗摔坏了」+ 库存 −1 | 给“挡在路中间”一个真实代价 | A13 |
| 推车掉水/出界/实体被删 | 服务端判定丢失；推车回收到租赁点；FORCED → 自动结算 | error「推车已回收，正在结算」+ 账单里「推车回收费」 | 不能因为载具丢失就把玩家卡死 | A13 |
| 推车被其他玩家“抢” | 不允许：非车主不能抓车；推车不进入载具抢夺系统 | 非车主按 E：error「这不是你的推车」 | 这条线的押金是摊主的，不能被路人拖走 | A10、A13 |

### 9.5 摊位挡路与场景冲突

| 事件 | 服务端动作 | 玩家看到 | 理由 | 验收 |
|---|---|---|---|---|
| 摊位摆在车道/路口 | 摆放校验直接拒绝 | PLACE-04 / PLACE-05 | 不允许“先摆再罚款” | A11 |
| 摊位旁停了车 | 校验占用体积，拒绝 | PLACE-06 | 车会挡顾客走位 | A11 |
| 摊位旁有另一个摊位 | 最小间距校验，拒绝 | PLACE-07 | 防止叠摊和顾客抢位 | A11、A18 |
| 摊位放在斜坡 | 坡度校验，拒绝 | PLACE-08 | 推车会滑/穿模 | A11 |
| 摊位放在禁区 | 区域多边形校验，拒绝 | PLACE-09 | 保护地标和任务点 | A11 |
| 摊位摆好后被车撞 | 同 §9.4 的推车翻倒流程 | 翻倒 + 扶正提示 | 场景是动态的，摆好不等于永远安全 | A13 |

### 9.6 身份/职业变化

| 事件 | 服务端动作 | 玩家看到 | 理由 | 验收 |
|---|---|---|---|---|
| 摊主下班（onduty=false） | 允许当前会话走完；新租借拒绝 | 当前 HUD 不变；租赁点 error「先上班再租推车」 | 不能因为到点下班就把正在卖的东西没收 | A12 |
| 摊主换职业 | 如果新职业不是 hotdog：FORCED → 自动结算 | error「你已不在岗，摊位自动结算」 | 防止用别的职业继续吃热狗收益 | A12 |
| 玩家被管理员踢下线 | 同断线；宽限期内可恢复 | 重连 toast | 管理操作不应该吞押金 | A12 |

### 9.8 依赖/组件不可用

| 缺失/异常 | 玩家看到 | 处理 | 理由 | 验收 |
|---|---|---|---|---|
| qb-minigames 导出失败 | error「小游戏暂时不可用，请联系管理员」 | 不扣原料、不产出；写服务端日志 | 不能让玩家按了 E 却什么都不发生 | A4 |

## 10. UX 交付标准与验收清单

### 10.1 UX 交付标准（人在游戏里按清单打勾）

| ID | 标准 | 怎么验（真机步骤） | 通过条件 |
|---|---|---|---|
| A1 | 每个交互点都有可见提示，不存在“走过去没反应” | 从租赁点 → 推车 → 摆放 → 烤架 → 顾客 → 车尾 → 归还区，每个位置停 3 秒 | 每个位置都出现 3D 文字或主提示；没有一处空白 |
| A2 | 每个阶段都有阶段名和下一步动作 | 走完一整局，每进入一个阶段看 HUD/3D/手机任务 | 玩家不用问“现在该干嘛” |
| A3 | 每一笔钱的变化都有即时 toast 或账单行 | 租借、每一笔成交、每一次回收、结算 | 钱的变化都有文字；没有静默加减 |
| A4 | 每个失败分支都有人话原因和下一步 | 按 §9.7 逐条触发：余额不足、挡路、原料空、成品满、顾客走、超时、掉线、被抢 | 每条都有原因 + 动作，不出现“操作失败”四个字 |
| A5 | 关键动作有动画和音效，不瞬移 | 抓车、推车、放下、开卖、做热狗、成交、收摊 | 每个动作都有可见动画；声音不叠、不刺耳 |
| A6 | 账单至少六类明细，关闭后可回看 | 结算后数行；关闭；再回租赁点打开 | 押金/租金/售出/成品回收/原料回收/税/净额齐全；能重开 |
| A7 | 摊位 HUD 常驻显示成品、原料、顾客、已售、押金、时间 | 营业中随机抽查 5 次 | 六项都在；数字与账单一致 |
| A8 | 顾客报价有耐心倒计时，接受/拒绝/无视都有反馈 | 分别成交、拒绝、放着不管 | 三种结果都有不同文案和声音；顾客不会凭空消失 |
| A9 | 做热狗完成立刻显示品质；取消不扣原料 | 分别做 0 失误、1 失误、≥2 失误；再按 Esc 退出 | 三档 toast 不同；退出后原料数量不变 |
| A10 | 玩家顾客能通过 target 购买；售罄/打烊/摊主不在有明确状态 | 用第二个账号走到摊位前按 ALT | 能买；三种不可买状态都有字；钱和货对称 |
| A11 | 摆放预览红/绿 + 具体原因；合法位置能一次成功 | 在车道、路口、车旁、斜坡、禁摆区各试一次，再在绿框试一次 | 每种红色都有不同原因；绿框一次确认成功 |
| A12 | 断线重连后摊位还在、押金状态可见；超时/重启有账单 | 拔网线 10 秒/2 分钟；重连；看 HUD 和租赁点 | 摊位还在；押金显示托管；超时有账单 |
| A13 | 超时 T-15/T-5/T-1 提醒；死亡/被抢/被捕/推车被撞有提示 | 把计时改短或真机等；分别死亡、被抢、被捕、撞车 | 每个事件都有 toast/error；没有静默状态变化 |
| A14 | 频率/距离校验失败有可见反馈，不允许静默 | 远距离按 Y、连续点购买、连续按 E 做热狗 | 每种都有具体 error；不会“点了没反应” |
| A15 | 中英文案完整、长度适配、不截断 | 中英文各走一局；看 1080p 和 1440p | 没有截断、没有机翻、没有中英混排错位 |
| A16 | 颜色不是唯一信息载体 | 关掉颜色/看灰度截图 | 品质有 ★/◆/●；金额有 +/−；状态有文字 |
| A17 | HUD 不与 qb-hud 重叠；右侧列表不同时出现 | 1080p/1440p 截图对比；ALT 打开时看右侧 | 不重叠；ALT 列表出现时 custom-prompt 列表隐藏 |
| A18 | 同屏 NPC 顾客 ≤ 1；不叠人；下一位在前一位离开后出现 | 连续营业 10 分钟，观察摊位前 | 最多 1 个顾客；没有两个顾客重叠；没有排队堵路 |
| A19 | 账单数字可对账；分项之和 = 净额；售出不重复计入 | 用计算器按账单逐行加；对 HUD 的已售金额 | 分毫不差；售出标「已付现」；净额只算押金块 |
| A20 | 重复结算/重复租借/重复成交幂等，不重复打钱 | 连点确认租借、连点结算、同一报价按两次 Y | 第二次不重复扣/退；显示“已结算/已成交” |
| A21 | 手机任务 App 的阶段文案与 HUD 一致；完成/失败/挂起都有条目 | 每个阶段打开手机任务 App | 阶段名一致；结束状态不残留“进行中” |
| A22 | 非车主/路人看到正确的只读状态，不会误触管理 | 第二个账号对推车/摊位/顾客按 E、ALT | 看到「别人的摊位/打烊中/这是别人的顾客」；不能管理 |

### 10.4 Definition of Done

一条热狗 UX 切片算“完成”，必须同时满足：

1. A1–A22 全部打勾，或未打勾项在验收单上写明原因和负责人；
