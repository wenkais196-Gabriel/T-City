# v0.3 基础设施层

## 版本目标

在 v0.2 基础 RP 稳定后，建立整个服务器的底层基础设施：统一经济出口、多标签职业体系、模块激活（服装/帮派/门锁）、管理工具和 Discord 审计。

本版本是所有后续特色系统（v0.4 手机 / v0.6 领袖 / v0.6 民间经济）的前置依赖，必须在本版本完成后才能安全展开上层开发。

> **并行注意**：v0.4 自研手机开发可在本版本第 2 周同步启动，不必等本版本完全验收。

---

## 实施范围

- 建立统一经济出口（AddScaledMoney）
- 建立安全边界（Rate Limit / 服务端校验 / 伪造事件拦截）
- 建立多标签职业体系数据库与 API（custom-career）
- 激活服装、帮派、门锁模块
- 建立管理员工具和 Discord 审计日志

## 一、统一经济系统（custom-economy）

### 设计原则

- 所有资金和物品变更必须通过 `AddScaledMoney` 统一出口，不直接调用 QBCore Money API
- 奖励倍率、价格倍率、冷却时间通过 Convar 配置，支持热调节
- 高价值操作强制写入日志

### 资源结构

#### [MODIFY] `resources/[custom]/custom-main/`
```lua
-- 统一资金出口（所有资源的奖励/购买必须调用此函数）
function AddScaledMoney(source, amount, reason)
  -- 1. 读取当前倍率 Convar
  -- 2. 校验职业、距离、权限
  -- 3. 检查冷却时间
  -- 4. 写入经济日志
  -- 5. 调用 QBCore:AddMoney
end
```

#### [NEW] `resources/[custom]/custom-economy/`
```
custom-economy/
├── fxmanifest.lua
├── config.lua          # Convar 读取、默认倍率配置
└── server/
    ├── economy.lua     # 统一经济事件处理器
    └── logs.lua        # 高价值资金/物品变更日志写入
```

`config.lua` 关键 Convar：
```cfg
# configs/modules/economy.cfg
set economy_wage_multiplier    "1.0"    # 工资倍率（催化剂卡牌会修改此值）
set economy_price_multiplier   "1.0"    # 商店价格倍率
set economy_log_threshold      "5000"   # 超过此金额的操作写入日志
set economy_cooldown_seconds   "60"     # 高价值操作默认冷却时间

# 催化剂卡牌倍率上限（硬保护，防止通胀失控）
set catalyst_max_wage_multiplier "2.0"
set catalyst_max_stack           "1"
set catalyst_global_cooldown     "3600"
```

## 二、安全边界（custom-security）

### 设计原则

- 客户端只能请求，不能决定结果
- 服务端校验距离、职业、权限、物品、冷却时间
- 高风险事件加 Rate Limit

#### [NEW] `resources/[custom]/custom-security/`
```
custom-security/
├── fxmanifest.lua
└── server/
    ├── ratelimit.lua   # 事件频率限制（按 source+事件名 计数）
    ├── validator.lua   # 距离校验、职业校验中间件
    └── antispoof.lua   # 客户端伪造事件检测与封禁
```

重点审计事件清单（继承自 v0.2 预记录）：
```text
AddMoney / RemoveMoney / AddItem / RemoveItem
SetJob / SetGang / GiveWeapon
车辆生成 / 商店购买 / 犯罪奖励 / 任务奖励
```

#### [NEW] `configs/modules/security.cfg`
```cfg
ensure custom-security
```

### 验收标准
- 客户端直接触发 AddMoney 等高风险事件被服务端拦截
- 同一玩家在 60 秒内超过 10 次触发同一高风险事件自动 kick
- Rate Limit 不误伤正常操作频率

## 三、多标签职业体系基础（custom-career）

### 为什么需要这个系统

QBCore 原生 `job.name + job.grade` 无法满足：
- 跨部门身份区分（县东局警察 vs 市区局警察）
- 多层级任务派遣（给"所有基层"统一推任务）
- 资质证书体系（飞行执照、船舶驾照）

### 数据库扩展（第 3 周一次性建完所有表）

```sql
-- 扩展 players 表（不破坏原有结构）
ALTER TABLE players
  ADD COLUMN rank_tier    VARCHAR(20) DEFAULT 'entry',
  ADD COLUMN department   VARCHAR(50) DEFAULT NULL,
  ADD COLUMN district     VARCHAR(50) DEFAULT NULL,
  ADD COLUMN certs        JSON        DEFAULT '[]';

-- 职业资质证书注册表
CREATE TABLE career_certifications (
  cert_id       VARCHAR(50) PRIMARY KEY,
  name          VARCHAR(100),
  required_role VARCHAR(50),
  required_tier VARCHAR(20)
);

-- 领袖岗位状态表（供 v0.6 使用，提前建好）
CREATE TABLE leader_roles (
  role         VARCHAR(20) PRIMARY KEY,
  citizenid    VARCHAR(50),
  name         VARCHAR(100),
  assigned_at  DATETIME,
  kpi_points   INT DEFAULT 0
);

-- KPI 任务记录表（供 v0.6 使用）
CREATE TABLE leader_kpi_tasks (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  leader_role  VARCHAR(20),
  task_type    VARCHAR(50),
  target_tags  JSON,
  assigned_to  VARCHAR(50),
  status       VARCHAR(20) DEFAULT 'pending',
  created_at   DATETIME DEFAULT NOW(),
  completed_at DATETIME
);

-- 催化剂卡牌状态表（供 v0.6 使用）
CREATE TABLE catalyst_cards (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  card_type    VARCHAR(50),
  activated_by VARCHAR(50),
  activated_at DATETIME,
  expires_at   DATETIME,
  is_hidden    BOOLEAN DEFAULT FALSE
);

-- 初始证书数据
INSERT INTO career_certifications VALUES
  ('pilot_license',   '飞行执照',   'civilian', 'entry'),
  ('marine_license',  '船舶驾照',   'civilian', 'entry'),
  ('heavy_vehicle',   '重型车驾照', 'civilian', 'entry'),
  ('firearms_cert',   '执法枪械证', 'police',   'entry'),
  ('surgical_cert',   '外科资质',   'medic',    'mid');
```

### 资源结构

#### [NEW] `resources/[custom]/custom-career/`
```
custom-career/
├── fxmanifest.lua
├── config.lua              # 职业定义、层级权限、晋升条件
├── server/
│   ├── main.lua            # 标签读写、晋升降职逻辑
│   └── certs.lua           # 资质证书发放/吊销
├── client/
│   └── main.lua            # 本地身份状态缓存（登录时同步）
└── shared/
    └── roles.lua           # 职业/层级/部门常量定义
```

核心 API（供所有其他资源调用）：
```lua
-- 获取玩家完整身份标签
exports['custom-career']:GetPlayerIdentity(source)
-- 返回：{ primary_role, rank_tier, department, district, certs }

-- 设置层级（管理员指令用）
exports['custom-career']:SetPlayerTier(source, tier)
exports['custom-career']:SetPlayerDepartment(source, dept)

-- 检查标签（用于任务派遣过滤）
exports['custom-career']:PlayerMatchesTags(source, { role="police", tier="entry" })
```

### 职业层级定义（v1.0 Beta 范围）

```lua
-- shared/roles.lua
ROLES = {
  police   = { label = "警察",   tiers = {"leader","mid","entry"} },
  medic    = { label = "医护",   tiers = {"leader","entry"} },
  mayor    = { label = "市长",   tiers = {"leader","entry"} },
  gang     = { label = "帮派",   tiers = {"leader","mid","entry"} },
  civilian = { label = "平民",   tiers = {"entry"} },  -- 民间经济职业
}

RANK_TIERS = {
  leader = { label = "领袖", permissions = {"kpi_terminal","catalyst"} },
  mid    = { label = "中层", permissions = {"dept_manage"} },
  entry  = { label = "基层", permissions = {} },
}
```

## 五、管理工具（custom-admin）

### 设计原则

- 管理员操作必须有权限校验（不允许普通玩家调用）
- 所有管理指令执行后写入 Discord `#admin-log` 频道
- 领袖指派/撤销指令必须实时同步 `custom-career` 的 `rank_tier` 字段

#### [NEW] `resources/[custom]/custom-admin/`
```
custom-admin/
├── fxmanifest.lua
├── config.lua      # 管理员权限列表（steamid 白名单）
└── server/
    └── commands.lua
```

核心指令：

| 指令 | 参数 | 说明 |
|------|------|------|
| `/setleader [id] [role]` | id=玩家ID, role=mayor/sheriff/gangboss | 指派领袖，同步更新 rank_tier=leader |
| `/demote [id] [reason]` | - | 即时剥夺领袖头衔，同步更新 rank_tier=entry |
| `/settier [id] [tier]` | tier=leader/mid/entry | 设置玩家层级 |
| `/setdept [id] [dept]` | - | 设置玩家部门 |
| `/setjob [id] [job] [grade]` | - | 快捷设置职业 |
| `/setgang [id] [gang] [grade]` | - | 快捷设置帮派 |

```lua
-- 指派领袖示例
RegisterCommand('setleader', function(source, args)
  -- 1. 权限校验（仅 admin）
  -- 2. 写入 leader_roles 表
  -- 3. 调用 custom-career:SetPlayerTier(target, 'leader')
  -- 4. 通知 custom-phone 解锁领袖 App
  -- 5. 推送 Discord #admin-log
end)
```

#### [NEW] `configs/modules/admin.cfg`
```cfg
ensure custom-admin
```

## 六、Discord 审计日志（custom-logs）

#### [NEW] `resources/[custom]/custom-logs/`
```
custom-logs/
├── fxmanifest.lua
├── config.lua      # Discord Webhook URL 配置（不进公开仓库）
└── server/
    └── webhooks.lua
```

**审计频道规划**：

| 频道名 | 推送内容 | 触发条件 |
|--------|----------|----------|
| `#economy-log` | AddMoney / RemoveMoney 超阈值 | 金额超过 `economy_log_threshold` |
| `#combat-log` | Combat Logging 警告 | 残血（HP < 120）或手铐状态下退服 |
| `#leader-log` | 领袖任命、KPI完成、催化剂卡牌使用 | 对应事件触发 |
| `#admin-log` | 所有管理员指令执行记录 | 任意 admin 指令执行 |
| `#error-log` | 服务端阻塞级错误 | 服务端 Lua 错误捕获 |

Webhook 消息格式（颜色编码）：
```lua
-- 经济日志（黄色警告）
SendDiscordEmbed('#economy-log', {
  color = 0xFFCC00,
  title = "💰 经济事件",
  fields = {
    { name = "玩家", value = citizenid },
    { name = "金额", value = amount },
    { name = "原因", value = reason },
    { name = "时间", value = os.date() }
  }
})
```

#### [NEW] `configs/modules/logs.cfg`
```cfg
ensure custom-logs
```

> **安全注意**：Discord Webhook URL 必须存放在 `server.cfg` 的 `set` 变量中，通过 `GetConvar` 读取，不得硬编码在资源代码中，不得进入任何公开代码仓库。
