# v0.6-quest 通用任务系统（Quest/Mission System）

## 版本目标

建立一套数据驱动、高性能、高安全的通用任务系统（Quest/Mission System），作为服务器所有「步骤式玩法」的通用基础设施。

本版本是 v0.6a（民间经济）和 v0.6b（领袖+卡牌）的**前置基础设施**。先建好任务系统，后续版本不再需要各自手写状态机/步骤管理/冷却/奖励统一出口。

> **核心设计**：任务逻辑与具体玩法解耦。任务模板通过配置文件定义（数据驱动），外部自研脚本通过标准 API（`OnCustomEvent` / `CompleteStep` / `RegisterStepValidator`）与任务系统联动。
>
> **开发策略**：完成度优先，周期不限。本版本以验收标准为准，不设硬性截止日期。确保核心状态机稳定 + 安全守卫完备后，再进入下一阶段。

## 设计背景

### 现存问题

在现有架构中，多个系统存在「隐性任务逻辑」的重复实现：

| 系统 | 隐性任务逻辑 | 重复了什么 |
|------|-------------|-----------|
| `custom-trucking`（规划中） | 接单 → 取货 → 送货 → 验证 → 结算 | 步骤状态机、距离校验、冷却、奖励 |
| `custom-mining`（规划中） | 前往矿点 → 采集 → 收集矿石 | 位置触发、进度追踪、冷却 |
| `custom-leaders` 市长工程 | 发布工程 → Job Board → 接单 → 完成 | 任务发布、状态管理、验证 |
| `custom-leaders` 警长巡逻 | 选巡逻区 → 逐点到访 GPS 路点 | 步骤序列、签到验证 |
| `custom-leaders` 帮派指标 | 下指标 → 全员贡献 → 集体结算 | 组进度追踪、计时器、奖励分发 |

**统一任务系统将上述所有场景抽象为一套通用的「步骤状态机」，彻底消除重复代码。**

## 实施范围

- 数据驱动任务模板系统（Config → Lua 表 → 运行时注册）
- 核心状态机（Not Started → In Progress → Step N → Completed / Failed）
- 6 种步骤类型：`reach`、`collect`、`script_trigger`、`custom_event`、`validator`、`reward`
- 外部脚本联动 API：`OnCustomEvent`、`CompleteStep`、`RegisterStepValidator`、`TriggerQuest`
- DB 持久化：`player_quests`、`quest_cooldowns`、`quest_event_log`
- 内存缓存层（复用 core-framework 三层 TTL 模式）
- 纵深安全防御（距离校验 / 物品验证 / 顺序强制 / Nonce Token / Rate Limit）
- 手机端任务追踪 UI（集成到 `custom-phone` Job Board）
- 模块 cfg：`quest.cfg` + 测试套件

## 数据库表

```sql
-- 玩家任务进度
CREATE TABLE IF NOT EXISTS player_quests (
    id              INT AUTO_INCREMENT PRIMARY KEY,
    citizenid       VARCHAR(50) NOT NULL,
    quest_id        VARCHAR(64) NOT NULL,
    status          VARCHAR(20) NOT NULL DEFAULT 'in_progress',
    --  'not_started' | 'in_progress' | 'completed' | 'failed' | 'abandoned'
    current_step    VARCHAR(64) DEFAULT NULL,
    progress_data   LONGTEXT DEFAULT NULL,     -- JSON 灵活存储步骤级进度
    started_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    completed_at    DATETIME DEFAULT NULL,
    failed_at       DATETIME DEFAULT NULL,
    completion_count INT DEFAULT 0,
    UNIQUE KEY uq_player_active_quest (citizenid, quest_id, status),
    INDEX idx_citizenid (citizenid),
    INDEX idx_status (status)
);

-- 任务冷却
CREATE TABLE IF NOT EXISTS quest_cooldowns (
    citizenid       VARCHAR(50) NOT NULL,
    quest_id        VARCHAR(64) NOT NULL,
    expires_at      DATETIME NOT NULL,
    completion_count INT DEFAULT 0,
    PRIMARY KEY (citizenid, quest_id),
    INDEX idx_expires (expires_at)
);

-- 任务事件审计日志
CREATE TABLE IF NOT EXISTS quest_event_log (
    id              INT AUTO_INCREMENT PRIMARY KEY,
    citizenid       VARCHAR(50) NOT NULL,
    quest_id        VARCHAR(64) NOT NULL,
    step_id         VARCHAR(64) DEFAULT NULL,
    event_type      VARCHAR(32) NOT NULL,  -- trigger | advance | complete | fail | abandon
    metadata        LONGTEXT DEFAULT NULL, -- JSON 上下文
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_citizenid (citizenid),
    INDEX idx_created (created_at)
);
```

## 对外 API 设计

### 核心 7 个 Exports

```lua
-- 1. 接取任务
exports['custom-quest']:TriggerQuest(src, 'quest_id')
--  → success (boolean), message (string)

-- 2. 通用事件桥（外部脚本只需广播事件，任务系统自动判断）
exports['custom-quest']:OnCustomEvent(src, 'event_name', { ...data })
--  → 无返回值，异步推进匹配的步骤

-- 3. 直接完成某一步（外部脚本明确知道自己在推进哪个任务时使用）
exports['custom-quest']:CompleteStep(src, 'quest_id', 'step_id')
--  → success (boolean)

-- 4. 注册步骤校验器（外部脚本作为步骤裁判）
exports['custom-quest']:RegisterStepValidator('validator_id', function(src, data)
    -- 返回 true/false, message
end)

-- 5. 强制失败
exports['custom-quest']:FailQuest(src, 'quest_id', 'reason')

-- 6. 查询活跃任务
exports['custom-quest']:GetActiveQuests(src)
--  → { { quest_id, title, current_step, progress_data }, ... }

-- 7. 查询任务进度
exports['custom-quest']:GetQuestProgress(src, 'quest_id')
--  → { status, current_step, progress_data, steps = { { id, title, done }, ... } }
```

### 外部脚本集成示例

```lua
-- custom-mining/server/main.lua
-- 矿工挖到矿石后，只需加一行代码：
RegisterNetEvent('custom-mining:server:mineCompleted', function(oreType, qty)
    local src = source
    local Player = QBCore.Functions.GetPlayer(src)
    if not Player then return end

    Player.Functions.AddItem(oreType, qty)  -- 正常发放物品

    -- ★ 通知任务系统（不影响正常逻辑）
    if exports['custom-quest'] then
        exports['custom-quest']:OnCustomEvent(src, 'mine_ore', {
            ore_type = oreType,
            quantity = qty,
        })
    end
end)
```

## 安全设计

| 攻击面 | 防御 |
|--------|------|
| 客户端伪造完成事件 | 服务端 `GetEntityCoords(ped)` 拉坐标，不信任客户端 |
| 事件重放 | Nonce Token + Rate Limit 滑动窗口 |
| 跳过步骤 | 服务端严格顺序强制，不接受客户端指定 step_id |
| 同角色多开刷任务 | DB `UNIQUE KEY (citizenid, quest_id, status)` |
| 外部脚本伪造 OnCustomEvent | 事件内捕获 `source`，不信任第一个参数 |
| 恶意注册校验器 | `RegisterStepValidator` 只允许在资源初始化时注册 |

## 模块 cfg

```cfg
# configs/modules/quest.cfg
ensure custom-quest
```

自定义资源在 `configs/modules/custom.cfg` 中注册为启动顺序中的一环（`custom-quest` 应在 `custom-phone` 之后、`custom-leaders` 和 `custom-mining` 之前加载）。
