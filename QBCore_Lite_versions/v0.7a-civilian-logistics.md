# v0.7a 载具系统重构与通用物流任务系统集成

## 版本目标

重构原版载具钥匙系统（废弃 `qb-vehiclekeys`），实现完全自主研发、高安全、高性能、模块化、易拓展的 **`custom-vehicles`** 资源，解决元数据膨胀与客户端 Tick 轮询开销。

同时，依托已有的 `custom-quest` 状态机，开发一套通用的**“物流运输任务模板（General Logistics Template）”**，以“自有卡车/飞机运货获得全额收益”为改装动力，以“租用过渡原厂车扣除 20% 费用”为新手保底，打磨车尾装货、低空雷达检测及掉线保护等细节交互，提升载具玩家的游戏体验。

---

## 实施范围

- **自研载具钥匙与生命周期管理器 (`custom-vehicles`)**：
  - 服务端权威的 `GiveKeys` / `RemoveKeys` / `HasKeys` 内存级 O(1) Cache，不存储临时钥匙到 DB 数据库。
  - 事件驱动架构：取消客户端高频轮询，通过 `gameEventTriggered` 监听玩家进出载具事件，空闲时 Tick 开销为 0。
  - 向下兼容桥梁：实现 `qb-vehiclekeys` 旧版 exports 与事件，作为无缝替代。
  - 任务载具追踪：在服务端通过 Plate 和 NetID 监控任务载具损坏、落水和遗弃，超时未坐回自动触发 Cleanup。
- **物流货运通用任务模板**：
  - 私家车所有权验证：匹配 `citizenid` 校验私车车牌与类别，作为任务车并给予 100% 收益。
  - 租车过渡逻辑：扣除固定押金及 20% 收益抽成，生成 stock 原厂卡车/飞机作为 fallback。
  - 精细交互：车尾/机尾按 E 装货、搬运进度条、车辆实体挂载货箱 Prop、车内按 E 交付、物理还车、掉线 5 分钟重连恢复。
  - 航空防空雷达警报：飞行高度 > 150 米触发 HUD 闪红警告。
- **打磨上线 3 个演示任务**：
  - 🚚 `euro_trucking_steel` (欧卡重载陆运 — 工业钢材配送)
  - ✈️ `aviation_smuggling_flight` (欧卡飞机版 — 走私飞行员)
  - 🚗 `vehicle_chop_shop` (轻量化偷车与拆解)

## 核心设计规范

### 1. 载具系统四大原则重构

#### A. 安全性 (Security)
- 严禁任何客户端单向通过 `AcquireVehicleKeys` 注入钥匙。
- 客户端的 Hotwire (热线发动) 或 Lockpick (撬锁) 事件上报必须包含 `vehNetId`，服务端强制进行物理距离校验（`#(GetEntityCoords(player) - GetEntityCoords(veh)) < 5.0`）。
- 验证玩家背包中确实拥有 `lockpick` 工具（如果是撬锁操作），校验通过后由服务端分发 Keys。
- 任务/NPC等临时钥匙仅驻留于服务端 Cache 内存中，不保存至 metadata 或写入 MySQL 数据库，玩家下线或任务清理时自动释放。

#### B. 高性能 (Performance)
- 废除原版 `qb-vehiclekeys` 中高频轮询的 `robKeyLoop` 线程（0ms - 100ms 频繁调用 `robKeyLoop` 导致 CPU 占用率高）。
- 客户端使用 `gameEventTriggered` 监听 `CEventNetworkPlayerEnteredVehicle`：
  ```lua
  AddEventHandler('gameEventTriggered', function(name, args)
      if name == 'CEventNetworkPlayerEnteredVehicle' then
          local player = args[1]
          local vehicle = args[2]
          if player == PlayerId() then
              -- 仅在玩家进入载具的瞬间触发钥匙检查与发动拦截
              CheckVehicleKeysOnEntry(vehicle)
          end
      end
  end)
  ```
- 服务端钥匙查询缓存采用 `[plate] = { [citizenid] = true }` 结构的哈希表，实现 O(1) 速度响应。

#### C. 兼容性 (Compatibility)
- 完美暴露以下 legacy exports，保证原有车库 (`qb-garages`) 和职业脚本直接调用正常：
  - `exports['qb-vehiclekeys']:HasKeys(plate)` -> `custom-vehicles:HasKeys(plate)`
  - `exports['qb-vehiclekeys']:GiveKeys(id, plate)` -> `custom-vehicles:GiveKeys(id, plate)`
  - `exports['qb-vehiclekeys']:RemoveKeys(id, plate)` -> `custom-vehicles:RemoveKeys(id, plate)`

### 2. 自有车优先 vs. 租车过渡机制 (Player Vehicle Priority & Rental)

在通用的物流运输模板中，我们引入所有权判定来激活改装动力：

```
                      玩家发起任务 check-in
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
   检测到符合要求的玩家私家车           未检测到私家车 (或主动选择租车)
            │                                 │
            ├────────────────► 绑定该私家车   ├────────────────► 扣除租金/押金
            │ (车牌、NetId、改装属性)         │ (扣除 15%-25% 收益抽成)
            │                                 │
            ▼                                 ▼
    享受 100% 任务收益结算              体验基础原厂性能 Benson/Duster
    (改装引擎提速 → 跑得更快赚更多)    (速度慢、操控一般)
```

1. **自有车所有权校验**：
   - 当玩家将卡车/飞机开进货运装载区时，任务步骤挂载 `validate_logistics_vehicle` 校验器。
   - 服务端首先获取当前驾驶车辆的车牌（Plate），与 `player_vehicles` 中该玩家 the `citizenid` 绑定记录匹配。
   - 匹配通过且车型类别符合任务要求的 allowed_classes 时，将该载具的 NetID 写入任务进度，玩家将获得 100% 收益结算。
2. **新手租车过渡**：
   - 玩家若未拥有相关重卡/飞机，或主动选择租车，系统生成原厂配置 Benson/Duster 作为过渡车，需要扣除 flat 押金（如 $500），且在最终奖励发放时扣除配置比例的 **20% 费用**。
   - 租车必须物理开回退车点以收回押金，不可通过后台指令强制删除，保持游戏世界的真实性。
3. **分级维护与加油**：
   - 私家车在运输中产生损耗：自助修理点（DIY）只可恢复发动机至 80%；玩家机修工店（Player Mechanic）才可恢复 100% 性能加清洁。
4. **非阻塞任务队列 (Non-Blocking Queue)**：
   - 任务冷却时间不阻碍玩家接单，玩家完成上一单并退还卡车后，可以立刻接取下一单不同的运单，确保持续流畅的游戏节奏。

- [ ] 外部车库调用 `exports['qb-vehiclekeys']:HasKeys` 成功桥接。
- [ ] 玩家驾驶**非本人名下**的重卡前往装货，系统验证失败，自动提示“载具非法”，无法推进装货步骤。
- [ ] 选择租车过渡后，扣除 $500 押金，生成 Benson。任务结算时，原收益 $2000 实收 $1600 (抽走 20%)，并自动退还押金，租用 Benson 只能物理开回还车点，否则押金没收且不自动清理。

- [ ] 走私飞行员任务中，驾驶 Duster 爬升超过 150 米触发闪红警告，降回 120 米警告立刻消失。
- [ ] 自动化测试套件 `test_refactored_vehicles.lua` 100% 运行通过。
