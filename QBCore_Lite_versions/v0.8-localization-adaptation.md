# v0.8 客户端自适应多语言本土化架构系统

## 版本目标

为了提升服务器的国际化能力和双语玩家的极致体验，本版本设计了一套**“零性能开销、对插件侵入性极低”的客户端自适应多语言本土化架构**。该系统彻底打破了传统 QBCore 只能通过 `server.cfg` 全局死板设定单一语言的限制，能够根据玩家客户端的 GTA V 原生语言设置（通过 `GetCurrentLanguage()` API），动态为玩家匹配并呈现对应的界面文本（中/英），同时设计了优雅的“未翻译回退机制”和“服务端通知本土化模式”，为服务器未来的国际化扩展奠定坚实的技术底座。

---

## 实施范围

- **客户端语言检测引擎 (Language Detection Engine)**：
  - 调用客户端原生 API `GetCurrentLanguage()` 智能感知玩家客户端的系统语言设置。
  - 判定条件：返回值若为 `9` (繁体中文) 或 `10` (简体中文)，自动选择 `zh-cn` 语言包；其余所有情况默认回退至 `en` (英文) 语言包，确保 100% 稳定运行。
- **多语言包注册表系统 (Global Locale Registry)**：
  - 重构所有翻译字典（如 `en.lua` 和 `zh-cn.lua`），改用全局注册表设计（`Locales['en'] = Translations`），使翻译内容常驻内存供动态调度。
  - 在最先载入的语言包（如 `en.lua`）中将 `Lang` 声明为空占位表（`Lang = {}`），优雅阻止未修改的原版语言包（如 `ar.lua`、`es.lua`）盲目抢先初始化全局 `Lang` 变量。
- **客户端自适应重载核心 (Client Locale Dynamizer)**：
  - 在客户端脚本（如 `client/main.lua`）的最顶部，拦截并根据玩家客户端检测到的实际语言重构 `Lang` 变量，将其实例化为对应的 `Locale` 类。
  - 动态重构后，客户端向 NUI（Vue/JS 界面）发出的翻译字典会自动替换为玩家对应的母语版本，实现 **0 行前端 HTML/JS 更改，100% 动态自适应界面语言**。
- **服务端静态默认回退 (Server-side Default Fallback)**：
  - 服务端（如 `server/main.lua`）依然读取 `server.cfg` 中配置的全局 Convar `qb_locale` 来初始化服务端的 `Lang`。
  - 这能保证服务器终端（F8/Console）的指令描述、后台输出和全局公告的语言统一性。
- **服务端至客户端特定通知本土化 (Localized Server Notifications)**：
  - 改变以往由服务端翻译直接推送通知的设计（这会导致中文服务器的英文玩家收到中文通知）。
  - 对于由服务端触发的针对特定玩家的本地化提示（如“角色注销成功”），改由服务端触发客户端事件，交由玩家客户端利用其已经动态本地化的 `Lang` 进行本地化弹出，实现完美的通知翻译匹配。

## 模块架构与联动逻辑

### 1. 客户端多语言智能加载流程

```mermaid
graph TD
    A[玩家载入 client 资源] --> B[加载 locales/*.lua 翻译定义]
    B --> C[注册至全局表 Locales['en'] 和 Locales['zh-cn']]
    C --> D[执行 client 脚本头部初始化]
    D --> E[调用 GetCurrentLanguage 获取游戏客户端语言]
    E --> F{是否为 9(繁中) 或 10(简中)?}
    F -- 是 --> G[选择中文: clientLang = 'zh-cn']
    F -- 否 --> H[回退英文: clientLang = 'en']
    G --> I[执行 Lang = Locale:new 重新实例化 Lang 变量]
    H --> I
    I --> J[NUI 打开时: 自动抽取当前 Lang 中的 ui. 翻译并推送至前端]
    J --> K[前端 HTML/Vue 呈现完美自适应语言的界面]
```

### 2. 服务端特定通知本土化联动

```mermaid
graph TD
    A[玩家在前端点击注销角色] --> B[NUI 触发 callback 并发送 Server 事件]
    B --> C[服务端 qb-multicharacter 逻辑执行删除操作]
    C --> D[服务端不再直接 Lang:t 发送 Notify]
    D --> E[服务端向特定玩家触发 Client 事件: qb-multicharacter:client:notifyCharacterDeleted]
    E --> F[玩家客户端收到事件, 调用已自适应的 Lang:t('notifications.char_deleted')]
    F --> G[客户端弹出符合玩家客户端语言的本地化 Notify]
```

## 性能与维护规范

### 1. 性能指标证明 (Performance Metrics)
* **CPU 开销**：`GetCurrentLanguage()` 和 `Locale:new()` 的实例化仅在玩家载入资源时**执行一次**，在日常游戏运行期，由于使用的是原版 Lua $O(1)$ Hash 查表逻辑，**CPU 额外计算开销为 0**。
* **内存开销**：中英两套翻译表（每套约 2-3 KB）两两常驻在客户端内存中，这相比于客户端动辄 8GB/16GB 的运存，**内存额外开销仅占几万分之一，完全可以忽略不计**。
* **网络开销**：全部语言包均在玩家进服下载资源包时存入本地，文本的查询和 NUI 的推送均在玩家本地电脑的内存中完成，**完全不占用任何外部网络带宽**。

### 2. 优雅回退与防呆规范 (Robust Fallback)
为了防止未来新加的非官方/自定义插件由于没有配置中文而导致报错，系统遵循以下加载防呆逻辑：
```lua
-- 若玩家客户端为中文，但该插件只配了英文包 Locales['en']，无 Locales['zh-cn']
-- 自动优雅地回退到英文，绝对不会报 nil 错误导致脚本中断
Lang = Locale:new({
    phrases = Locales[clientLang] or Locales['en'] or {},
    warnOnMissing = true
})
```

## 验收标准

- **中文测试组**：当使用中文语言的游戏客户端进入服务器时，多角色选择界面（如“我的角色列表”、“创建新角色”、“注销角色”等）以及公寓选点界面（如“确认选点”、“上次离线位置”等）必须 100% 呈现中文，无漏译或乱码。
- **英文测试组**：当使用英文语言的游戏客户端进入服务器时，完全相同的资源在界面上必须 100% 呈现英文。
- **缺失回退性测试**：当故意删除 `locales/zh-cn.lua` 文件时，中文客户端玩家在进服时能够平滑回退显示英文界面，不产生任何 Lua 脚本中断、报错或黑屏现象。
- **特定通知测试**：注销角色成功的通知，中文客户端看到“角色已成功注销！”，英文客户端看到“Character deleted!”。

## 后续施工指引（待服务器基本完成后的本土化适配）

当服务器的基本功能组件和自定义逻辑开发完毕后，您可以开启此版本的施工：
1. **统一重组资源 fxmanifest.lua** 中的加载文件，保证 `locale.lua` 率先加载，`en.lua` 紧随其后。
2. **重构语言字典**，改用全局 `Locales['xx']` 注册格式。
3. **注入客户端自适应重载核心**。
4. 将特定通知重构为**服务端通知本土化模式**。
