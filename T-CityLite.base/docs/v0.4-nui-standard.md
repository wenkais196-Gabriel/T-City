# v0.4 NUI 现代化标准与测试手册

本手册为服务器 NUI (HTML5 UI) 的重构与后续新建资源（如手机、HUD、MDT、背包等）确立了 **TypeScript + Svelte + Vite** 的现代化技术标准。我们以 `qb-banking` 为首个重构样板资源，实现了极致的类型约束、消息流控制与浏览器级 Mock 交互开发体验。

---

## 1. 架构与目录规范

所有符合现代化标准的 NUI 资源均应采用以下工程组织模式。工程主体采用 Svelte 5 + TS 开发，Vite 负责工程化打包，并将打包产物输出至 `html` 供游戏直接读取。

### 目录结构树

```text
qb-banking/
├── html/                     # [自动生成] 打包产物目录，被游戏直接加载
│   ├── assets/               # Vite 编译混淆后的 JS 与 CSS
│   └── index.html            # NUI 入口页面
├── web/                      # [源码目录] 前端独立工程，开发工作在此进行
│   ├── src/
│   │   ├── assets/           # 静态素材（图标、本地资源等）
│   │   ├── components/       # UI 业务功能组件
│   │   │   ├── ATMView.svelte      # ATM 交互组件
│   │   │   └── BankDashboard.svelte# 银行网点交互组件
│   │   ├── types/            # TypeScript 类型约束契约
│   │   │   └── index.ts      # 包含 PlayerData, Account, Statement 等定义
│   │   ├── utils/            # 通讯套件与底层驱动
│   │   │   └── nui.ts        # NUI 桥接 + 浏览器仿真 Mock 引擎
│   │   ├── App.svelte        # UI 根控制器与状态机
│   │   ├── app.css           # 全局设计系统样式（色值、微动画、响应式）
│   │   └── main.ts           # Svelte 5 初始化挂载点
│   ├── index.html            # 浏览器调试的入口模板
│   ├── package.json          # 依赖管理
│   ├── vite.config.ts        # Vite 打包策略配置文件
│   └── tsconfig.json         # TS 编译配置
├── client.lua                # 客户端 Lua 脚本 (NUI 回调处理)
├── server.lua                # 服务端 Lua 脚本 (数据存取与安全防刷)
└── fxmanifest.lua            # 资源声明清单 (指向 html 资源路径)
```

## 2. 核心技术要素与开发标准

### 2.1 零阻碍联调：浏览器仿真 Mock 引擎
在以往开发中，修改 UI 后需要重启服务器甚至登录游戏进行验证，效率低下。
在新标准下，`web/src/utils/nui.ts` 引入了**仿真 Mock 引擎**。它能够：
1. **环境自适应**：通过检测 `window.GetParentResourceName` 是否存在，自动识别当前处于**普通浏览器**还是**游戏内**。
2. **交互闭环仿真**：在普通浏览器中拦截所有 `fetchNui` 触发的请求（如存取款、转账、管理用户等），在前端内存中模拟数据库的自增、划扣与流水添加，并返回与 Lua 格式完全一致的 `{ success: true/false, message: "..." }` 响应。
3. **开发模式快捷面板**：在浏览器预览时，右下角会浮现独立的 `NUI PREVIEW PANEL`，点击即可一键触发 `openBank` 或 `openATM` 初始化广播，方便直接切换大屏终端和 ATM 物理机。

> [!TIP]
> **本地开发命令**：
> ```bash
> cd web
> npm run dev
> ```
> 打开浏览器对应的本地地址，即可完成 **100% 的 UI 逻辑、样式、微动画与错误状态联调**！

### 2.2 五M NUI 桥接通信规范

#### 1. Lua 向 NUI 推送消息 (`SendNUIMessage`)
统一采用 `action` 字段进行广播分发。
* Svelte 组件中，通过 `registerNuiEvent` 方法安全绑定。此方法在 Svelte 组件的 `onMount` 生命周期中注册，并在 `onDestroy` 销毁时**自动解绑**，完美杜绝了 UI 关闭后残留全局事件监听引发的内存泄露。
```typescript
// Svelte 示例：
import { registerNuiEvent } from '../utils/nui';

registerNuiEvent('openBank', (data) => {
  playerData = data.playerData;
  accounts = data.accounts;
  // 更新状态...
});
```

#### 2. NUI 向 Lua 反馈请求 (`fetchNui`)
统一使用 `fetchNui` 异步函数，在 Lua 侧处理完后，利用 `cb(data)` 返回成功或错误状态。
```typescript
// TS 示例：
const res = await fetchNui<{ success: boolean; message: string }>('withdraw', {
  accountName: 'checking',
  amount: 500,
  reason: 'ATM Cash Withdrawal'
});

if (res.success) {
  // 操作成功，更新本地 UI 状态，弹出成功 Notification
} else {
  // 操作失败，弹出错误 Notification
}
```

### 2.3 高性能交付规范
- **打包体积控制**：没有引入大型组件库（如 Element, Vuetify）或 Tailwind，全 Vanilla CSS 编写极致轻量。最终打包产物中，CSS 仅 **28KB**，JavaScript 仅 **85KB**，首字节加载延迟近乎于零。
- **打包路径兼容**：在 `vite.config.ts` 中配置 `base: './'`，使得导出的 `index.html` 以相对路径引用 CSS/JS。这解决了 FiveM 下 `nui://resource-name/html/index.html` 协议由于无法解析绝对路径（如 `/assets/index.js`）导致黑屏的硬伤。

## 3. 测试验证手册 (Testing Manual)

为确保新重构的 UI 样板能够无瑕疵运行，请按照以下三个场景逐步测试。

### 场景 A：浏览器极致预览测试 (免进游戏)
1. 打开终端，进入 `qb-banking/web`。
2. 运行本地开发服务：
   ```bash
   npm run dev
   ```
3. 在 Chrome/Edge 浏览器中打开显示的 `http://localhost:5173/`。
4. **测试步骤**：
   - **登录/切换**：点击右下角浮动的预览面板 `Bank Branch` 或 `ATM Screen`。
   - **大厅网点 (Bank Branch)**：
     - 切换左侧 `checking` 与 `Family Savings` 账户，观察中间银行卡样式、卡号（CID）与流水明细是否动态同步。
     - **存款测试**：在 checking 账户存款 `$1000`，填入 Memo，确认后 pocket cash 应实时扣减，bank balance 实时增加，并在底部流水单上追加一条带绿色箭头的 statement 记录。
     - **取款测试**：存款后，尝试取款 `$500`，确认 pocket cash 实时增加，bank 扣减，流水单追加红色带箭头 records。
     - **内部转账**：在 `checking` 中选择 `Internal Transfer`，目标账户选择 `Family Savings`，转入 `$5000`。点击确定，两个账户的余额需立即同步变动。
     - **开户/销户**：在左侧下方输入 `Business Account`，选为 `shared` 共享账户，初始注入 `$1000`，确认后新账户实时被追加入列表；选择新账户，在 Access Control 的 Danger Zone 中点击 `Close Account`，该账户消失，且 `$1000` 资金划转回 `checking`。
     - **权限管理**：选择 `Family Savings` 共享卡，进入 Access Control，在 `Authorized Citizens` 列表中可以看到已有授权者。输入 Citizen ID `WKS12345`，点击 `Add User`，该用户需立即排入列表；点击已存在非 OWNER 用户的 `Revoke` 按钮，该用户立即从授权单消失。
   - **ATM 网点 (ATM View)**：
     - 点击右下角 `ATM Screen`。界面应显示**怀旧数码荧光绿的 CRT 终端**，并要求输入密码。
     - 密码输入错误（不是 `1234` 或 `1111`）时，敲击回车或点击 `ENTER` 键，应在屏幕上方闪烁显示红底的 `INVALID SECURITY PIN CODE`，密码框重置。
     - 密码输入 `1234` 点击回车，成功进入 ATM 蓝本。
     - 验证 `QUICK CASH` 快速提款按键（$50, $100, $500），点击后应立刻完成划转并切换至 `TRANSACTION APPROVED` 确认界面。
     - 点击 `WITHDRAW AMOUNT`，手动使用屏幕金属键盘或你的**实体物理键盘**输入取款金额，验证 `CLEAR` 擦除、`CANCEL` 取消与 `ENTER` 回车确定功能。

### 场景 B：打包与资源装载测试
1. 在 `qb-banking/web` 目录下执行：
   ```bash
   npm run build
   ```
2. 检查 `qb-banking/html` 目录，确保已存在 `assets` 目录，且里面含有编译后的 `.css` 和 `.js`。
3. 检查 `qb-banking/fxmanifest.lua`，确保 `files` 字段中已包含 `'html/assets/*'`，以动态引用 Vite 输出的所有带 Hash 资源。

### 场景 C：游戏内挂载与运行测试
1. 启动 FiveM 局域网服务器。
2. 走近任意 Maze Bank 网点（或通过控制台输入 `ensure qb-banking`）。
3. **唤起 UI 测试**：
   - 走进网点交互区按 `E` 键（或使用 qb-target 准星对准柜员），验证大厅主界面是否伴随**柔和的 Slide 动画**瞬间弹出，且角色焦点成功捕获（无法控制人物行走，能使用鼠标操作 UI）。
   - 走近 ATM 机插入 bank_card 卡片，验证 ATM 翠绿荧光终端是否完美载入。
4. **游戏内功能闭环测试**：
   - 进行存取款操作，验证玩家身上的物理 cash 道具数量及数据库中的 bank 字段数据是否随之联动。
   - 转账给其他玩家，验证转账后两者的数据库金额及 statement 变动情况。
5. **UI 销毁清理测试**：
   - 点击右上角或右下角退出图标，或者按下键盘的 **`Esc`** 键。
   - 验证 NUI 焦点是否完全消除，角色重获行使控制权，屏幕不再残留任何 UI 图层。
   - 连续多次开/关 UI，确认游戏 FPS 稳定，控制台（F8）无任何报错与定时器越界警告。

## 4. 后续系统改造升级参照指南

当你准备推进 **v0.5 犯罪玩法**，或者后续需要对 **手机 (qb-phone)**、**HUD (qb-hud)**、**警用 MDT** 实施重构时，可以直接复制本项目 `web/` 的工程结构：
1. **直接迁移组件**：修改 `vite.config.ts` 中的 `outDir` 指向目标资源的静态目录，即可使用这套极致流畅的打包体系。
2. **重写 API Mock**：在 `web/src/utils/nui.ts` 中针对新资源的 Lua 逻辑编写 Mock 数据池，便可在浏览器中单独无阻碍开发和调整 UI，保障大项目的绝对稳定性。
