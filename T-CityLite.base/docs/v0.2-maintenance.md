# T-City Lite v0.2 技术维护文档

本文档记录 `T-CityLite.base` v0.2 的基础角色扮演（RP）模块启动结构、资源边界、OneSync 修复、数据库依赖和排错维护规则。目标是确保在精简、模块化的 Lite 架构下，RP 核心闭环的稳定维护与扩展。

## 版本目标

v0.2 在 v0.1 的最小启动链基础上，构建了最小 RP 功能闭环：

- **基础职业框架**：支持设置玩家职业与等级，并完成基础上下班（On Duty / Off Duty）以及通过 `qb-management` 进行的账目/雇员管理。
- **基础经济操作**：玩家能查看银行账户，完成基础的存款、取钱与转账。
- **基础车辆管理**：玩家可以使用钥匙锁车/开锁，并通过 `qb-garages` 完成公共车库、职业车库的存取车和状态保存。
- **警察基础执法**：警察职业可正常加载，支持上岗、基础互动（搜身、拷人、押解等）和警察专属菜单。
- **医院医疗流程**：倒地死亡、呼叫 EMS、病床治疗、复活重生以及死亡状态的跨连接持久化。
- **修复语音系统**：通过启用 OneSync，完美解决了 v0.1 中 `pma-voice` 资源无法加载的遗留问题。

本版本继续坚持“小闭环、低耦合”原则，暂不启用门锁（`qb-doorlock`）、监狱（`qb-prison`）、手机（`qb-phone`）和车辆零售（`qb-vehicleshop`）等重度复杂依赖模块。

## 启动入口与 OneSync 机制

### 启动入口
保持与 v0.1 相同的启动路径：
```powershell
cd D:\txData\T-CityLite.base
D:\server\FXServer.exe +exec server.cfg
```

### OneSync 核心变更
由于 QBCore 核心组件以及 `pma-voice` 语音模块底层深度依赖虚拟实体同步，必须开启 OneSync 才能保证客户端不发生局部断连及语音失效。
在 `server.cfg` 中做出了以下关键调整：
```cfg
## Network
endpoint_add_tcp "0.0.0.0:30120"
endpoint_add_udp "0.0.0.0:30120"
sv_maxclients 48
set onesync on  # 开启 OneSync，解决 pma-voice 启动依赖
```

## 新增模块 CFG 职责与资源关系

v0.2 引入的全新模块 CFG 的启动资源及其职责规划如下：

### 1. configs/modules/jobs.cfg
负责全局职业进度条与 boss/职级账户管理：
```cfg
ensure progressbar      # 警察执法、医生治疗、锁车等交互进度条
ensure qb-management    # 统一的雇员管理、账目划扣、企业资金流水管理
```
* **维护规则**：由于 `qb-bossmenu` 已被官方弃用，在此通过启用 `qb-management` 完全接管所有 boss 交互，请勿重新启用 `qb-bossmenu`。

### 2. configs/modules/banking.cfg
负责全服金融交互：
```cfg
ensure qb-banking       # 银行柜台/ATM交互，支持检查、存取、转账与日志
```
* **依赖说明**：依赖底层数据库中的 `bank_accounts` 与 `bank_statements` 数据库表。

### 3. configs/modules/vehicles.cfg
负责车辆钥匙锁定、燃油与车库存取流程：
```cfg
ensure qb-fuel          # 导出 LegacyFuel 接口，供警察、医生及普通车库使用
ensure qb-vehiclekeys   # 接管车辆钥匙逻辑（锁车、开锁、钥匙授权与偷车交互）
ensure qb-garages       # 基础车库功能，读取 player_vehicles 数据
```
* **注意**：`qb-garages` 配置文件中需显式配置 `Config.FuelResource = 'LegacyFuel'` 以兼容燃油同步。

### 4. configs/modules/police.cfg
负责警察执勤与互动核心：
```cfg
ensure qb-policejob     # 警察值勤状态、更衣室、局内仓库、警局证据库、犯人拘留及指令菜单
```
* **依赖关系**：警察局内部很多动作（如拷人、搜身）强依赖 `progressbar`；罚单与证据操作需读取 `qb-banking` 与背包组件。

### 5. configs/modules/medical.cfg
负责医院救治与复活生命线：
```cfg
ensure qb-ambulancejob  # EMS 值勤、倒地状态、呼叫系统、病床治疗、就地医疗和医院复活
```
* **注意**：倒地与复活状态在玩家下线重连时，通过 `qb-core` 底层保存的 meta 属性（如 `isdead` / `inlaststand`）自动恢复，修改此逻辑请谨慎。

## 数据库维护

v0.2 新增的功能底层有较强的结构化数据库支持。在排查问题前，请确保以下三个数据表完好无损：

1. **`bank_accounts` (银行账目表)**
   - 存储企业、组织（如 `police`, `ambulance`）或帮派的共享经济账目（`account_balance`, `account_type` 等）。
2. **`bank_statements` (银行对账单)**
   - 存储交易记录以作日志跟踪（金额 `amount`、事件原因 `reason`、类型 `statement_type`、时间戳 `date`）。
3. **`player_vehicles` (玩家载具资产表)**
   - 存储车库中玩家合法拥有的载具（板牌 `plate`、车库位置 `garage`、燃油度 `fuel`、引擎/外观受损值 `engine`/`body`、存车状态 `state`）。

* **排查提示**：若玩家存取车后重新登录车辆状态重置，或者银行操作报错，请第一时间使用 `D:\MariaBD\bin\mysql.exe` 查询这三张表是否存在异常锁死或字段残缺。

## 常见排错与维护指引

### 1. PMA-Voice 语音失效或提示 OneSync 报错
* **现象**：服务端抛出 `OneSync needs to be enabled` 或玩家无法进行距离语音交互。
* **解决方法**：检查 `server.cfg` 中是否存在 `set onesync on`。如果没有，补上后重启服务端。

### 2. 存取车辆时报错或者状态不保存
* **现象**：在车库点存车，车辆不消失；或者提取车辆时提示失败。
* **原因分析**：
  - 数据库缺少 `player_vehicles` 表，或者表中的 `plate` 字段与其他模块（如车店）类型冲突。
  - `LegacyFuel` 导出接口故障。
* **处理方法**：检查 `qb-garages/config.lua` 中的配置，确保 `Config.FuelResource` 设置为 `'LegacyFuel'` 且该资源在 `qb-garages` 之前正确启动。

### 3. 设置职业（/setjob）无反应或提示 boss 菜单不可用
* **原因分析**：
  - `qb-core/shared/jobs.lua` 中配置的职业等级（grade）或 `onduty` 配置不符合要求。
  - 调用了已被废弃的 `qb-bossmenu` 事件。
* **处理方法**：确保 `jobs.cfg` 中加载的是 `qb-management`，并在定义新职业时，正确分配 `isboss = true` 的等级以支持 boss 资金账户。

### 4. 倒地死亡状态丢失
* **原因分析**：
  - 玩家倒地后强退，重连后状态恢复为健康，破坏 RP 体验。
  - 这是因为 `qb-core` 保存 meta 数据发生延迟或底层 `qb-ambulancejob` 未将 `isdead` 属性正确上报。
* **处理方法**：在 `qb-core` 的 `Save` 事件中捕获玩家 Metadata，确保底层逻辑在玩家强退时仍能写入 `players` 表的 `metadata` 字段。

## 进入 v0.3 安全与开发预警

为配合后续 **v0.3 统一经济系统** 的开发，我们需要在 v0.2 的维护中注意收集以下安全和数据日志：

1. **资金流审计口径**：
   - 重点监控 `qb-banking` 的服务端 Callback `qb-banking:server:deposit`、`qb-banking:server:withdraw` 和 `qb-banking:server:transfer`。
   - 检查客户端是否能直接通过触发这些事件任意存取不属于自己的资金。
2. **职业赋权安全**：
   - 检查 `qb-management` 在雇佣、解雇以及修改工资时，服务端是否验证了触发者确实拥有 `isboss` 权限。
3. **载具生成与存储**：
   - 重点检查 `qb-garages` 在提取车辆时，有无二次验证该车辆是否确实属于该玩家的 `citizenid`，防止利用板牌（Plate）伪造刷车。

## 维护原则

1. **坚持按模块拆分 CFG**：绝不为了图方便将新增的 RP 资源写死在 `core.cfg` 或 `server.cfg` 中。
2. **渐进式依赖恢复**：不要因在控制台看到缺失依赖报错，就盲目启动整个 `[qb]`。所有高级依赖（如门禁、手机、监狱等）必须经过盘点并作为 v0.2 之外的分级模块分步开启。
3. **每次验证必查 OneSync 与 Voice 状态**：任何影响 `server.cfg` 的变动都必须确保 `set onesync on` 没有被覆盖，否则会导致语音链路彻底瘫痪。
