## 2. 核心架构变更

### 2.1 便利店抢劫：客户端驱动 → 服务端权威计时器

```
旧: 客户端 isDone=true → 服务端发奖（可作弊提前触发）
新: 客户端 startRobbery → 服务端 SetTimeout(25000) → 到点自动发奖
```

**关键数据结构** (`server/main.lua`):
```lua
activeRobberies[registerId] = {
    src = source,          -- 玩家 ID
    timer = timerHandle,   -- SetTimeout 句柄
    startTime = ms,        -- 开始时间（用于计算倍率）
    cancelTime = ms|nil    -- 逃跑时间（nil=没逃跑）
}
```

### 2.2 警察门槛：Convar → GlobalState

```
旧: GetConvar("crime_min_police_storerobbery", "2") 
    → QBCore 权限问题导致 SetConvar/ExecuteCommand 报错
新: GlobalState:set('crime_min_police_storerobbery', value, true)
    → 所有资源自动可见，无需额外权限
```

### 2.3 qb-weathersync 时间推进

**Bug 修复**: 原代码 `tick - 22 > tick` 永远为 false，秒数永不推进。

```
旧: 本地推进小时/分钟 → SyncTime 每 2 秒拉回 → 分钟跳变
新: 小时/分钟从 baseTime+timeOffset 每帧计算（与服务器一致）
    仅 second 本地推进（每 22ms +1，到 60 归零）
```

## 6. 常见问题排查

### 手机不显示游戏时间

```
检查步骤:
1. 服务器日志是否有 [phone] GameTime=... 输出
   有 → Lua 端正常，问题在前端 JS（检查 JSON.parse 是否已修复）
   无 → Lua 端崩溃（检查 os.date 是否已替换）
2. 前端修补: html/assets/index.js 中 "e.data" 不应有 "JSON.parse"
```

### 压力值不变化 (HUD stress ring 始终为 0 或无增减)

```
症状: 超速/射击后 HUD 压力环无变化；重新登录后压力显示 0

诊断流程:
1. 检查职业白名单 (最常见原因)
   - qb-hud/config.lua → Config.WhitelistedJobs
   - police (type=leo) 和 ambulance 默认豁免全部压力
   - 切到 civilian 职业验证

2. 检查服务器日志
   - 搜索 "GainStress" 确认服务端收到事件
   - 搜索 "Whitelisted" 确认是否被拦截

3. 已修复的已知 Bug (v0.7)
   - server.lua: nil 检查在访问 PlayerData 之后 → 静默崩溃 → 已修复
   - client.lua: 登录时 stress/hunger/thirst 未从元数据恢复 → 已修复
   - server.lua: ResetStress 死变量 + 反向钳位死代码 → 已清理
```

### 抢劫不给战利品

```
检查步骤:
1. 确保 custom-security、custom-crime、custom-economy 都在运行
2. 检查 exports 引用正确:
   - CheckRateLimit  → custom-security
   - CheckStoreRobbery → custom-crime
   - AddScaledMoney  → custom-economy
   - GetEconomyRewardScale → custom-economy
```

### 时间不变化或分钟回跳

```
检查步骤:
1. restart qb-weathersync 后 /time 12 00 是否生效
2. 查看 client/client.lua 中的时间线程:
   - hour/minute 应从 baseTime+timeOffset 计算
   - 不应有本地 hour/minute 递增逻辑
3. SyncTime 事件应只更新 baseTime/timeOffset，不直接设 hour/minute
```

## 7. v0.6 安全与性能加固 (Architecture Hardening)

### 7.1 DirtyFlush 脏数据批处理管道

`QBCore.Player.Save()` 已从直接 SQL 改为 DirtyFlush 管道代理：

```
旧: Save() → MySQL.insert (每 5 分钟 × 100 人 = 100 次全字段 UPDATE)
新: Save() → DirtyFlush.MarkDirty → 定时 15 分钟批量落盘
      force=true → DirtyFlush.ForceFlush (立即直接 SQL)
```

**关键文件**:
- `core-framework/cache/dirty_flush.lua` — ForceFlush 直接 SQL（避免循环调用）
- `qb-core/server/player.lua` — Save() 代理逻辑 + hunger/thirst 不标记 IsDirty

### 7.2 SecurityService 全链路校验

核心金钱/职业/帮派操作已接入 `Bus.SecurityService` 校验层：

| 函数 | 校验内容 |
|:-----|:--------|
| `AddMoney` / `RemoveMoney` / `SetMoney` | source 验证 + 金额清洗 + 单笔阈值 + 累计熔断 |
| `SetJob` / `SetGang` | source 验证 + 名称清洗 + 等级钳制 |

### 7.3 SQL 注入修复

`qb-management` sv_boss.lua + sv_gang.lua: `LIKE '%jobname%'` → `JSON_EXTRACT` 参数化查询。

### 7.4 弃用事件硬拒绝

`QBCore:Server:UseItem` / `RemoveItem` / `AddItem` → 安全日志 + 拒绝执行。

### 7.5 qb-hud Stress Handler 防御性加固

`hud:server:GainStress` / `RelieveStress` nil 检查前置到访问 `PlayerData.job` 之前，防止静默崩溃。移除死代码 `ResetStress` 变量及反向钳位分支。客户端登录时从 `PlayerData.metadata` 恢复 `stress`/`hunger`/`thirst` 本地值。

### 7.6 qb-banking Rate Limit

withdraw / deposit / internalTransfer / externalTransfer 均添加 2 秒冷却。
