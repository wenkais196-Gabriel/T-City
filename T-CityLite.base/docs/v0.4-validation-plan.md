## 一、四原则贯彻策略

### 🧩 模块化
| 要求 | 现状 | 措施 |
|------|------|------|
| 独立 Svelte 组件/App | ✅ 每个 App 独立目录 + Svelte 组件 | 验证目录结构完整性 |

### ⚡ 高性能
| 要求 | 现状 | 措施 |
|------|------|------|
| 关闭时 CPU ≈ 0 | ✅ isPhoneOpen 控制线程 | **实测** 100 次开关循环无泄漏 |

| 通知 ≤ 1 次/秒 | ✅ 服务端自然限制 | 验证推送频率 |
| 打包 < 250KB gzipped | 🔍 声称 180KB | **实测** 实际文件大小 |
| 消息列表 LIMIT 100 | ✅ SQL 层面限制 | 验证查询上限 |

### 🔒 安全
| 要求 | 现状 | 措施 |
|------|------|------|
| 输入长度校验 | ✅ name ≤ 30, message ≤ 500, content ≤ 200 | 测试边界值 |

| 领袖权限校验 | ✅ rank_tier ~= 'leader' 拒绝 | **实测** 非 leader 调用 |
| 距离校验 | ✅ completeJob 25m, shareContact 8m | **实测** 越界拦截 |
| 离线转账回滚 | ✅ DB 失败自动回滚 sender | **实测** 回滚原子性 |
| 数据库 SQL 注入 | ✅ 参数化查询 | 验证所有查询 |

### 🔌 可拓展

### Phase 2: 安全审计（Security Review）

#### Step 2.1 — 输入边界测试
- [ ] name > 30 字符 → 拒绝
- [ ] message > 500 字符 → 拒绝
- [ ] content > 200 字符 → 拒绝
- [ ] amount ≤ 0 → 拒绝
- [ ] 负数金额 → 拒绝
- [ ] 空字符串 → 拒绝
- [ ] SQL 特殊字符 → 参数化查询无害

#### Step 2.2 — 业务逻辑安全
- [ ] 自转账 → `Cannot transfer money to yourself`
- [ ] 余额不足 → `Insufficient checking balance`
- [ ] 非 leader 调用领袖 API → 拒绝
- [ ] completeJob 距离 > 25m → 拒绝
- [ ] shareContact 距离 > 8m → `walked too far away`
- [ ] 离线转账 DB 失败 → 自动回滚 sender

#### Step 2.3 — 事件注入防护
- [ ] 所有 `RegisterNetEvent` 校验 `source`
- [ ] bankTransfer 使用 `tonumber` 强制类型
- [ ] 无 `TriggerClientEvent` 泄露敏感数据

### Phase 3: 性能基线（Performance Benchmark）

#### Step 3.1 — 开关循环测试
- [ ] 连续开/关 100 次
- [ ] 每次关闭后验证 `isPhoneOpen == false`
- [ ] 100 次后检查有无残留线程
- [ ] CPU 占用 < 0.1ms/tick 平均

#### Step 3.2 — 打包体积
- [ ] 读取 `html/assets/` 目录总大小
- [ ] gzip 压缩后确认 < 250KB
- [ ] 如果超限：检查 Vite 配置（tree-shaking / 压缩）

#### Step 3.3 — 消息延迟
- [ ] 服务端发送 → 客户端接收 计时
- [ ] 平均 < 200ms
- [ ] 最大 < 500ms
