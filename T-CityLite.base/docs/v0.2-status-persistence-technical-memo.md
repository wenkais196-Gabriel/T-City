# T-City Lite v0.2 角色状态持久化与系统稳定性技术维护文档

本文档详细阐述在 T-City Lite v0.2 版本中，关于玩家角色持久化状态（健康度、护甲、饥饿/口渴代谢、伤病骨折状态）因换号/离线被重置的完整技术修复细节，以及 `qb-target` 底层运行时崩溃的技术改进方案。

---

## 1. 业务痛点与技术成因

在实机联调测试中，核心 RP 闭环存在以下四个关键的技术缺陷：

### 1.1 玩家代谢（饥饿/口渴）下线重置
* **成因**：当玩家登出或切换角色（触发 `QBCore:Client:OnPlayerUnload`）时，`qb-ambulancejob` 客户端调用了 `ResetAll()` 进行本地清理。
* **缺陷**：原版 `ResetAll()` 包含 `TriggerServerEvent('hospital:server:resetHungerThirst')` 逻辑。这导致每次玩家离线或切号时，服务端强制将该 CitizenID 的 `hunger` 和 `thirst` 写入 100 并存盘，抹去了真实的生理代谢状态。

### 1.2 角色血量上线强设满血
* **成因**：在 `qb-ambulancejob/client/job.lua` 的 `OnPlayerLoaded` 监听内，存在一个 5 秒的独立延迟线程：
  ```lua
  CreateThread(function()
      Wait(5000)
      SetEntityMaxHealth(ped, 200)
      SetEntityHealth(ped, 200)
  end)
  ```
* **缺陷**：此线程无视从数据库加载的生命值，上线 5 秒后强制将其刷新到 200（满血）。

### 1.3 肢体创伤/骨折（Limbs Injuries）离线消失
* **成因**：原版的伤病肢体状态（`limbs = BodyParts`）和流血数值仅临时存储在服务器 Lua 内存表 `PlayerInjuries` 里。
* **缺陷**：由于离线或换号时该数据未被序列化存入 `players` 的 `metadata` 中，每次玩家重新登录时均会被视作完美健康状态。

### 1.4 自定义“上线强制复活”覆盖了真实状态
* **成因**：为了解决 v0.1 阶段没有医疗脚本、玩家卡地形死亡无法复活的调试痛点，[custom-main](file:///d:/txData/T-CityLite.base/resources/%5Bcustom%5D/custom-main/client/main.lua) 被写入了上线强制触发 `hospital:client:Revive` 和健康重设逻辑。
* **缺陷**：在启用 `qb-ambulancejob` 后，该逻辑没有进行服务隔离判定，导致无论数据库保存的数据如何，上线均会被直接复活和完全治愈。

## 2. 解决方案与重构细节

我们针对上述链路实施了彻底的“本地隔离-底层扩展-主入口判定”三层重构：

### 2.1 底层存储扩展 (`qb-core`)
1. **默认字段扩充**：在 [config.lua](file:///d:/txData/T-CityLite.base/resources/%5Bqb%5D/qb-core/config.lua) 的 `PlayerDefaults.metadata` 中追加了默认生命值字段：
   ```lua
   health = 200,
   ```
2. **实时血量落盘**：在 [player.lua](file:///d:/txData/T-CityLite.base/resources/%5Bqb%5D/qb-core/server/player.lua) 的 `QBCore.Player.Save`（自动和手动存档接口）中，追加了对玩家 Ped 真实血量的读取与落盘序列化：
   ```lua
   if ped and ped ~= 0 then
       local phealth = GetEntityHealth(ped)
       if phealth > 0 then
           PlayerData.metadata['health'] = phealth
       end
   end
   ```
3. **强制登出落盘**：修改 `QBCore.Player.Logout` 接口，在触发卸载事件前强制调用 `Player.Functions.Save(true)`，保证正常登出时数据的实时性。

### 2.2 医疗逻辑重构 (`qb-ambulancejob`)
1. **客户端本地重置隔离**：在 [client/main.lua](file:///d:/txData/T-CityLite.base/resources/%5Bqb%5D/qb-ambulancejob/client/main.lua) 中重构，剥离了用于玩家下线清理的 `ResetAllLocal()` 函数。该函数只擦除本地客户端环境的变量，不向服务器发送任何同步事件，保护数据库的饱食度、饱水度与伤病存档不被重设。
2. **多角色换号隔离**：在 [server/main.lua](file:///d:/txData/T-CityLite.base/resources/%5Bqb%5D/qb-ambulancejob/server/main.lua) 中添加 `QBCore:Server:PlayerLoaded` 和 `QBCore:Server:OnPlayerUnload` 的状态挂钩，在换号或离线时，内存表 `PlayerInjuries` 与 `PlayerWeaponWounds` 立即重置，防止下一个使用相同 ID 槽位的玩家继承旧状态。
3. **伤病与生命复原**：重构 [client/job.lua](file:///d:/txData/T-CityLite.base/resources/%5Bqb%5D/qb-ambulancejob/client/job.lua) 的 `OnPlayerLoaded` 加载时序：
   * 优先检测 `PlayerData.metadata['health']` 和 `['armor']` 并直接恢复物理实体；
   * 从 `metadata['injuries']` 恢复肢体损害表 `BodyParts` 并重新激活残疾/流血的局部线程；
   * 若玩家上一次处于死亡/垂死状态（`isdead`/`inlaststand`），跳过血量恢复，交由死亡控制器直接处理。

### 2.3 自定义保护兼容优化 (`custom-main`)
在 [custom-main/client/main.lua](file:///d:/txData/T-CityLite.base/resources/%5Bcustom%5D/custom-main/client/main.lua) 中：
1. **医疗环境过滤**：将强制医疗复活和状态满值治疗的触发逻辑，修改为仅在 `GetResourceState('qb-ambulancejob') ~= 'started'`（即未启用正式医疗包的简易测试阶段）时生效。
2. 保持了 12 秒的防卡位无敌物理保护，完全避免了伤害覆盖。

## 3. 附带修复：`qb-target` 运行时系统崩溃

在对测试日志的排查中，同步解决了两处导致客户端脚本完全中断的经典 bug：

### 3.1 射线检测无效句柄崩溃 (L118)
* **缺陷成因**：在 `RaycastCamera` 击中虚空或非物理实体时，`entityHit` 返回 `0`，但因为在 Lua 中 `0` 为真，脚本强行运行 `HasEntityClearLosToEntity(0, playerPed, 7)` 导致 FiveM 引擎抛出 `0xfcdff7b72d23a1ac` 原生函数执行崩溃。
* **修复方法**：在 `client.lua` 的检测语句中加入句柄有效性及实体存在验证：
  ```lua
  if flag == 30 and entityHit and entityHit ~= 0 and DoesEntityExist(entityHit) then
  ```

### 3.2 区域高亮空指针崩溃 (L420)
* **缺陷成因**：当 Config 中开启 `DrawSprite` 且目标区域处于可见距离外时，`listSprite[closestZone.name]` 为空（`nil`）。此时无保护强行对 `.success` 赋值导致整个交互主循环停摆。
* **修复方法**：在 L420 处补全防穿透的空指针判定：
  ```lua
  if Config.DrawSprite and listSprite[closestZone.name] then
  ```

## 4. 维护与后续指南

* **新增持久化属性**：如果未来开发（如 v0.3）需要新增持久化字段，只需在 `qb-core/config.lua` 默认元数据中定义，并在 `qb-core/server/player.lua` 的 `Save` 流程中采集即可，不要在业务脚本中单独做重置写入。
* **自定义脚本边界**：`custom-main` 仅用于全局测试例外，涉及游戏性状态（生命值、金钱、职业）必须将权限归还给正式的核心 RP 包。
