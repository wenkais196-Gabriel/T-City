# T-City Lite v0.1 技术维护文档

本文档记录 `T-CityLite.base` v0.1 的启动结构、资源边界、依赖例外和后续维护规则。目标是让后续版本可以在稳定的最小启动链上继续扩展，而不是重新回到整组加载。

## 版本目标

v0.1 只保证 QBCore 服务器的最小可玩流程：

- 玩家可以连接服务器。
- 玩家可以创建或选择角色。
- 玩家可以完成出生流程。
- HUD、背包、天气同步、语音可以基本使用。
- `custom-main` 可以作为自定义逻辑入口启动。

本版本不追求完整 RP 功能，不主动启用大型玩法模块，例如警察、医院、抢劫、车店、房屋、电话、赛车等。

## 启动入口

主配置文件是：

```text
D:\txData\T-CityLite.base\server.cfg
```

推荐启动方式：

```powershell
cd D:\txData\T-CityLite.base
D:\server\FXServer.exe +exec server.cfg
```

`server.cfg` 只负责基础服务器配置、数据库连接、QBCore/语音 convar、权限和模块引入。资源启动顺序放在 `configs\modules` 内。

## 配置文件职责

### server.cfg

负责：

- 端口和客户端上限。
- 服务器名称、tags、license、locale、图标。
- `mysql_connection_string`。
- QBCore 基础 convar。
- pma-voice 基础 convar。
- `exec configs/modules/*.cfg`。
- 管理员权限和 QBCore 权限继承。

维护规则：

- 不在这里堆大量 `ensure`。
- 不再使用 `ensure [qb]`、`ensure [standalone]`、`ensure [voice]`、`ensure [defaultmaps]`。
- 新资源优先放入对应模块 cfg。

### configs/modules/core.cfg

负责基础运行环境和 QBCore 核心：

```cfg
ensure mapmanager
ensure chat
ensure spawnmanager
ensure sessionmanager
ensure basic-gamemode
ensure hardcap
ensure baseevents
ensure oxmysql
ensure qb-core
```

维护规则：

- 只放所有模块都依赖的底层资源。
- 数据库相关问题优先检查 `oxmysql` 和 `mysql_connection_string`。

### configs/modules/player.cfg

负责玩家进入服务器后的最小流程：

```cfg
ensure PolyZone
ensure qb-menu
ensure qb-input
ensure qb-target
ensure qb-interior
ensure qb-clothing
ensure qb-weathersync
ensure qb-apartments
ensure qb-spawn
ensure qb-multicharacter
ensure qb-weapons
ensure qb-inventory
ensure qb-hud
```

维护规则：

- 角色、出生、背包、HUD 相关资源放这里。
- 调整启动顺序时，优先保证依赖先启动。
- 如果玩家卡在选角或出生，优先看 `qb-multicharacter`、`qb-spawn`、`qb-apartments`、`qb-clothing`。

### configs/modules/voice.cfg

负责语音：

```cfg
ensure pma-voice
```

维护规则：

- 语音 convar 仍放在 `server.cfg`，资源启动放在这里。
- 如果语音范围、说话状态、无线电异常，先查 `server.cfg` 的 voice convar，再查客户端 F8。

### configs/modules/custom.cfg

负责自定义逻辑入口：

```cfg
ensure custom-main
```

维护规则：

- 自定义玩法优先从 `custom-main` 接入。
- 如果 `custom-main` 调用未启用的 job、police、crime、vehicle、house 等模块，应先临时注释调用，并记录到后续版本任务。

## 添加新资源的规则

添加资源时按这个流程走：

1. 先看资源的 `fxmanifest.lua`。
2. 找 `dependencies`、`dependency`、`@resource/file.lua` 引用。
3. 确认依赖资源是否已经启动。
4. 决定资源归属模块，例如 `player`、`voice`、`custom`，或为后续版本新增模块。
5. 只在对应模块 cfg 里新增 `ensure`。
6. 更新 `configs\disabled-resources-v0.1.md` 或新版本禁用清单。
7. 启动服务器并记录控制台/F8 错误。

不要因为一个资源报错就直接恢复 `ensure [qb]`。这样会让启动链重新失控。

## 停用资源的规则

停用资源前先确认：

- 是否有其他资源 manifest 明确依赖它。
- 是否有客户端脚本通过 `@resource/file.lua` 引用它。
- 是否有 server/client 事件、exports 或 shared object 调用它。
- 是否会影响登录、选角、出生、背包、HUD、语音这些 v0.1 核心流程。

如果不确定，先保留资源，并在禁用清单里记录“待确认”，不要直接删除资源文件。

## 常见排错入口

### 数据库错误

检查：

- `server.cfg` 的 `mysql_connection_string`。
- 数据库服务是否运行。
- 数据库名、用户名、密码是否正确。
- QBCore 所需表是否存在。

相关资源：

- `oxmysql`
- `qb-core`
- `qb-multicharacter`
- `qb-spawn`
- `qb-apartments`
- `qb-inventory`
- `qb-clothing`

### 角色选择异常

优先检查：

- `qb-multicharacter`
- `qb-core`
- `oxmysql`
- `qb-apartments/config.lua`

### 出生异常

优先检查：

- `qb-spawn`
- `qb-apartments`
- `qb-interior`
- `qb-clothing`
- `qb-weathersync`

### 背包异常

优先检查：

- `qb-inventory`
- `qb-weapons`
- `qb-core/shared/items.lua`
- 数据库中的玩家物品数据。

### HUD 异常

优先检查：

- `qb-hud`
- `qb-core`
- 客户端 F8 NUI/JS 错误。

### 语音异常

优先检查：

- `pma-voice`
- `server.cfg` 中的 `voice_*` convar。
- 客户端语音输入设备和 FiveM 设置。

- 保留原始 base：`D:\txData\QBCore_CDB34E.base` 不作为施工目录。
- Lite base 所有改动集中在 `D:\txData\T-CityLite.base`。
- 任何新增资源都必须有归属模块和依赖说明。
- 任何禁用资源都必须记录禁用原因和计划恢复版本。
- 每次能稳定启动后更新 changelog 和测试日志。
