> **修订日期**: 2026-06-04  
> **面向对象**: 本地单人开发者 & 协同 AI 编程 Agent  
> **核心宗旨**: 用轻量化的结构性规范，维持单人开发的高质高效，保障长期版本迭代不发生雪崩。

## 1. 人机协同开发工作流全景图

```
     ┌──────────────────────────────────────────────────┐

                              ▼
     ┌──────────────────────────────────────────────────┐
     │              2. 开发与联调 (Development)         │
     │      - 套用脚本模板，通过 NUI Mock 浏览器内调通 UI │
     └────────────────────────┬─────────────────────────┘
                              ▼
     ┌──────────────────────────────────────────────────┐
     │                3. 测试阶段 (Testing)             │

                              ▼
     ┌──────────────────────────────────────────────────┐
     │                4. 编写阶段 (Documenting)         │
```

## 2. 五大阶段标准执行规范

### 1. 规划阶段 (Planning Spec)
*   **依赖图审计**：在新增任何外部插件前，必须扫描其 `fxmanifest.lua` 中的 dependencies。确认依赖项已经在 `configs/modules/` 下的 CFG 中被 ensure，防止启动链断裂。
*   **参数建模**：优先在 `configs/modules/` 下设计本功能所需的控制参数（CVars），禁止在业务代码中硬编码任何关键数值（如奖励倍率、限制距离）。

### 2. 开发与联调阶段 (Development Spec)
*   **套用骨架**：服务端与客户端代码必须遵循 `script_templates.md` 的规范，保证初始化即具备 Logger 拦截与性能 Tick 节流。
*   **NUI 浏览器零阻碍开发**：
    *   所有包含前端 NUI 的模块，必须在 `web/` 下利用 Svelte 进行开发。
    *   **强制规定**：必须在 `nui.ts` 中编写 Mock 数据集，在浏览器端利用 `npm run dev` 完成 100% 的 UI 交互调试。
    *   **Vite 编译避坑**：打包配置中 `base` 必须设为 `'./'`，确保输出为相对路径，规避 FiveM 独有的 `nui://` 协议下绝对路径无法读取导致黑屏的硬伤。

### 3. 测试阶段 (Testing Spec)
*   **Layer 1 提交守卫**：在代码有物理级改动时，首先在终端运行 `python tests/run_all.py`，确认无循环依赖、无语法警告。
*   **Layer 2 游戏内逻辑回归**：
    *   开启 FiveM 本地测试服，键入 `/test run [模块名]`。
    *   断言输出必须达到 100% 成功。如用例失败，严格禁止进入下一阶段。

### 4. 编写阶段 (Documenting Spec)
*   **技术及运维文档同步**：
    *   根据 `technical_manual_spec.md` 新增/更新项目的技术手册。
    *   根据 `maintenance_manual_spec.md` 更新维护指南，记录本次变更涉及的物理文件、Convars 调整及排错方法。

### 5. 维护阶段 (Maintaining Spec)
*   **看板信息同步**：
    *   开发完成并验证通过后，在项目根目录手动或调用脚本更新 `PROJECT_PROGRESS.md` 中的看板进度。
    *   将本次修改简明记录在 `CHANGELOG.md` 中。
*   **运行时观测**：
    *   服务正常上线后，通过 Discord Webhook 观测 `#economy-log` 与 `#security-log`。
    *   如在 10 分钟内发生多起红色 `🚨 安全警报` 拦截，证明服务端配置（如距离或熔断额度）设定过窄，应根据维护手册的诊断指令动态微调 Convars 参数。
