# T-City Lite v0.3 基础设施层实机测试清单 (Test Checklist)

本清单专为 **v0.3 基础设施层**（以及重写的 **qb-banking 银行安全净化**）版本的实机测试设计，按功能模块划分子任务。您可以根据此清单在游戏中逐步进行测试，并记录实际运行中的反馈与报错。

---

## 🏦 模块一：银行对账重构与安全净化 (`qb-banking`)
*对应文档：[v0.3-banking-refactor.md](file:///d:/txData/T-CityLite.base/docs/v0.3-banking-refactor.md)*

### 📝 1.1 柜台柜员基础金融与对账单一致性测试
* **前提条件**：玩家登录，身上有 $10,000 现金，Checking 账户有 $5,000 存款。
* **测试步骤**：
  - [ ] 走向 Maze Bank 柜台，按 `E` 或使用 `ALT`（第三眼）唤起柜员面板。
  - [ ] 验证右上角 `Pocket Cash` 栏目是否实时显示为钱包内物理现金。
  - [ ] **存款**：向 Checking 账户存入 `$1,000`，备注填入 `Checking Deposit Test`。
  - [ ] **取款**：从 Checking 账户取出 `$500`，备注填入 `Checking Withdraw Test`。
  - [ ] **流水验证**：滚动至底部的 `TRANSACTION STATEMENTS`，查看交易流水。
* **预期结果**：
  - [ ] 存款后现金减 $1,000，Checking 账户增加至 $6,000。
  - [ ] 产生一条绿色带箭头记录：`+$1,000`，备注显示为 `Checking Deposit Test`。
  - [ ] 取款后现金加 $500，Checking 账户降为 $5,500。
  - [ ] 产生一条红色带箭头记录：`-$500`，备注显示为 `Checking Withdraw Test`。
  - [ ] 数据库 `bank_statements` 表中数据同步写入。

### 📝 1.2 子账户开户、对账与销户退款闭环测试
* **测试步骤**：
  - [ ] 在左侧 Sidebar `Create New Account` 区域，输入账户名 `Project-A`。
  - [ ] 设置类型为 `Shared`，初始存入金额填入 `$2,000`，点击 `Open Account`。
  - [ ] 检查 Checking 账户是否自动扣除 $2,000，且左侧生成新卡片 `Project-A`。
  - [ ] 切换至 `Project-A`，分别存入 `$500`（备注 `A-Deposit`）和取出 `$200`（备注 `A-Withdraw`）。
  - [ ] 检查 `Project-A` 的对账单历史。
  - [ ] 切换至 `Access Control` 面板，在 `Danger Zone` 中点击 `Close Account & Refund` 进行销户。
  - [ ] 切换回 Checking 账户检查其余额。
* **预期结果**：
  - [ ] 开户成功，Checking 自动划扣 $2,000，`Project-A` 初始余额为 $2,000。
  - [ ] `Project-A` 交易流水仅有一条开户初始注入记录：`+$2,000` (Initial deposit)。
  - [ ] 存取款后余额变为 $2,300，且流水中完美生成对应的 `+$500` 和 `-$200`。
  - [ ] 点击销户后，`Project-A` 卡片从 Sidebar 彻底消失。
  - [ ] Checking 余额立即增加 $2,300，且 Checking 流水单中新增一条备注为 `Refund from closure of Project-A` 的 `+$2,300` 存款对账记录。

### 📝 1.3 重名账户“幽灵”复活防漏测试（核心漏洞验证）
* **前提条件**：完成上述 1.2 的全部步骤（保证 `Project-A` 已产生流水、被注销退款）。**切勿重启服务器**。
* **测试步骤**：
  - [ ] 保持在线，再次走向柜台。
  - [ ] 在 `Create New Account` 区域输入**一模一样**的账户名：`Project-A`。
  - [ ] 初始注入资金填写 `$100`。
  - [ ] 点击 `Open Account` 开户。
  - [ ] 点击左侧新生成的 `Project-A` 账户，观察下方的 `TRANSACTION STATEMENTS`。
* **预期结果**：
  - [ ] `Project-A` 开户成功，余额显示为 `$100`。
  - [ ] 流水单**仅有**一条新开户记录：`+$100` (Initial deposit)。
  - [ ] 旧 `Project-A` 账户产生的任何历史流水（如前面的 $2,000/$500/$200）**均已彻底消失**，无任何幽灵数据、数据残留或串卡混淆。

### 📝 1.4 银行卡停用与 ATM 彻底失效测试
* **测试步骤**：
  - [ ] 登录柜台，切换至任意子账户并进入 `Access Control` 面板，观察右下角。
  - [ ] 使用管理员指令获取一张银行卡道具 `/giveitem bank_card 1`（或通过数据库/背包放置）。
  - [ ] 在背包中双击使用 `bank_card`。
  - [ ] 走近街头任意一台 ATM 机，使用 `ALT`（第三眼）聚焦 ATM。
* **预期结果**：
  - [ ] 子账户管理面板中，原本的 `Order Physical Debit Card` 按钮已被**彻底移除，无任何残留占位符**。
  - [ ] 背包中双击 `bank_card` 无任何反应，客户端与服务端控制台无报错。
  - [ ] 对准 ATM 实体进行 `ALT` 聚焦扫描，**无任何“打开ATM”选项浮现**。ATM 沦为纯净的街景装饰模型。

## 💰 模块二：统一经济与安全出口测试 (`custom-economy` & `custom-security`)
*对应规范：[v0.3-economy.md](file:///d:/txData/QBCore_Lite_versions/v0.3-economy.md)*

### 📝 2.1 统一资金 API 与倍率测试
* **测试步骤**：
  - [ ] 执行调用 `AddScaledMoney(source, amount, reason)`。
  - [ ] 验证系统是否正常读取 `configs/modules/economy.cfg` 的 Convar 配置（如倍率 `economy_wage_multiplier`）。
  - [ ] 当变更 convar 倍率时，验证实收金额是否按对应比例进行放缩缩放。
  - [ ] 尝试注入高价值金额，验证是否正常被 `economy_log_threshold` 记录并触发日志。

### 📝 2.2 服务端安全校验与 Rate Limit 测试
* **测试步骤**：
  - [ ] 使用测试脚本或触发器从客户端直接尝试触发高风险事件（如 `qb-banking:server:deposit` 或 `AddMoney`）。
  - [ ] 在 60 秒内连续触发同一个高风险事件超过 10 次。
* **预期结果**：
  - [ ] 客户端直接触发高风险事件时被服务端有效拦截。
  - [ ] 超频触发（Ratelimit 溢出）后系统自动将该恶意客户端 kick/封禁。

## 🏷️ 模块三：多标签职业体系基础 (`custom-career`)

### 📝 3.1 职业身份标签与 API 获取
* **测试步骤**：
  - [ ] 在游戏中登录角色，并在控制台/脚本中调用 `exports['custom-career']:GetPlayerIdentity(source)`。
  - [ ] 验证返回的数据结构是否包含主职业、层级、部门、地区及证书 JSON (例如：`{ primary_role, rank_tier, department, district, certs }`)。
  - [ ] 使用管理员指令变更角色属性（如 `SetPlayerTier` / `SetPlayerDepartment`），验证数据库 `players` 表中的对应字段与客户端缓存是否同步更新。

### 📝 3.2 帮派系统与门锁系统联动
* **测试步骤**：
  - [ ] 验证帮派职位或等级变化时，`custom-career` 的 `rank_tier` 字段是否自动完成联动映射（如教父映射为 `leader`）。
  - [ ] 靠近被激活门锁的警局、医院或帮派地盘，测试开关门。
  - [ ] 验证系统是否是读取 `custom-career` 的标签权限（不硬编码职业名）控制开关门。
