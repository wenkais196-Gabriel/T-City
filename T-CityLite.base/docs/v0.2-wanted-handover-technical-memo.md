# T-City Lite v0.2 - 警星移交与雷达追踪系统技术维护文档

本文档详细记录 `T-CityLite.base` 在 v0.2 阶段自定义集成的**“原生警星移交玩家警察 + 雷达三角追踪定位 + 市民恐慌躲避 + 警员同僚化防反击 + 通缉犯执勤锁死（防漏洞）”**系统的技术设计、目录结构、核心逻辑与安全防火墙配置。

## 🛠️ 系统架构与目录结构

所有自定义高品质 RP 通缉与追踪逻辑均封装在服务器核心资源 `[custom]/custom-main` 中，完全解耦，不破坏 QBCore 原生核心框架。

```text
D:\txData\T-CityLite.base\resources\[custom]\custom-main
├── fxmanifest.lua              # 清单文件，注册新增脚本

```

## 💾 核心机制技术详解

### 1. 警星移交机制（NPC 警车撤退）
* **文件位置**：`client/dispatch.lua`
* **工作原理**：
  客户端线程每 2 秒循环检测玩家的原生 Wanted Level（警星）。
  * 当警星达到 **1~2 星**：保留 GTA 5 原始警车和直升机刷新，作为玩家的轻量防线。
  * 当警星达到 **$\ge 3$ 星**：
    * 客户端捕获触发瞬间，锁定本地状态 `isCustomWanted = true`，并保存当时的原生警星值 `customWantedStars`。
    * **AI 警车撤退机制**：调用原生 Natives `ClearPlayerWantedLevel(playerId)` 与 `SetMaxWantedLevel(0)` 瞬间将原生警星清空并锁死，**完全阻止游戏引擎无限刷新 AI 警车与直升机**，防止杂乱的 NPC 警车摧毁玩家间的 RP 体验。
    * **首次通缉广播**：捕获当前逃犯的坐标及路段名（通过 `GetStreetNameAtCoord`），触发向服务端事件 `custom-main:server:policeHandoverAlert` 的单次首发通告。

### 2. 雷达三角追踪定位（GPS Triangulation Blips）
* **工作原理**：
  * **在逃端 GPS 脉冲**：逃犯客户端在 `isCustomWanted == true` 状态下，后台线程会以 **每 8 秒一次的频率** 向服务器发送最新的坐标与路段名。同时提示逃犯：“【警用直升机】你的 GPS 信号正被警方基站雷达三角定位，位置已被广播！”。
  * **警员端雷达渲染**：
    所有处于 **QBCore 执勤状态（police 职业且 onduty == true）** 的警员在收到服务端 GPS 脉冲广播后，会在自己的雷达和大地图上实时渲染一个**红色闪烁警徽 Blip（Sprite 161）**，并**自动绘制一条追踪导航红线**。
    * **脉冲消失**：Blip 在创建 12 秒后若没有收到逃犯下一个 8 秒的 GPS 更新，便会自动从警察雷达上销毁。这在防范“开图挂”的同时，完美模拟了**雷达定期扫描脉冲点**的真实 triangulation 追踪体验。

### 3. 被通缉逃犯专属：NPC 路人恐慌躲避力场
* **工作原理**：
  当玩家处于通缉在逃状态时，本地客户端会在其 **25 米** 范围内建立一个“市民恐慌力场”。
  线程每 1.5 秒通过 `GetGamePool('CPed')` 检索附近的所有路人 Ped。
  * **步行市民**：调用 `TaskFleePed` 强制其大叫并抱头跑开（30% 概率播放原生恐怖尖叫人声 `GENERIC_FRIGHTENED_HIGH`）。
  * **驾驶司机**：调用 `TaskVehicleTempAction(ped, veh, 9, 6000)` 触发车载临时恐慌驾驶，市民司机会在惊恐下**狂踩地板油加速逃离**嫌疑人所在的街道。
  * **过滤器**：安全排除了玩家自己、动物、死尸以及 `COP` 关系组（警察），保证执法环境真实顺畅。

### 4. 警员值班免疫及 NPC 警察“同僚化”
* **工作原理**：
  在客户端，当检测到玩家的 QBCore 职业为 `police` 且正在执勤（`onduty`）时：
  * 强行锁死其 Wanted Level 为 0，使其天然免受任何警星处罚。
  * 核心设置：`SetPedRelationshipGroupHash(ped, GetHashKey("COP"))`。
  * **NPC 警察友好反击免疫**：将玩家的实体关系组强行设置为 `COP`（同僚）。在 GTA 5 的 AI 行为树中，NPC 市民警察会将执勤警官判定为“自己人”，**即使玩家警官误伤了 NPC 警察（开枪误射、载具擦碰等），NPC 警察也绝对不会进行武力反击**，完全杜绝了警官在打击罪犯时被身边的 NPC 警员开火击杀的窘境。

### 5. 逃犯安全拦截（防 /duty 逃课 Exploit 漏洞）
* **工作原理**：
  防范下班警员在违法被通缉后，通过键入 `/duty` 强行恢复执勤状态来取巧洗白。
  * **指令层拦截**：在 `/duty` 指令入口，读取调用者的通缉状态缓存 `WantedPlayers` 以及数据库元数据 `metadata['wanted']`，若大于 0 则直接驳回指令。
  * **核心层锁死（OnJobUpdate 监听）**：
    由于玩家还可以去警局的值班点物理打卡，或者通过第三方脚本、菜单越权更改 duty 属性，我们在服务端直接架设了全局事件拦截网：
    ```lua
    AddEventHandler('QBCore:Server:OnJobUpdate', function(src, job)
        local Player = QBCore.Functions.GetPlayer(src)
        if not Player then return end
        local citizenid = Player.PlayerData.citizenid
        local savedWanted = Player.PlayerData.metadata['wanted'] or 0
        
        -- 如果逃犯企图以任何物理/第三方方式切换为上班状态
        if (WantedPlayers[citizenid] or savedWanted > 0) and job.onduty then
            -- 强制重置回下班状态，并弹出红字警告
            Player.Functions.SetJobDuty(false)
            TriggerClientEvent('QBCore:Notify', src, "【执勤拦截】你当前处于通缉在逃状态，无法打卡上班以逃避罪责！", "error", 8000)
        end
    end)
    ```

## 🏛️ 通缉数据销案与重置

当执勤警员使用 **`/clearwanted [玩家ID]`** 或 **`/clearwarrant [玩家ID]`** 后：
1. 服务端将嫌疑人从 `WantedPlayers` 内存缓存中抹去，并重写 `metadata['wanted'] = 0`。
2. 触发目标客户端的 `custom-main:client:clearLocalWanted` 重置事件：
   ```lua
   SetMaxWantedLevel(5) -- 恢复原生最大警星限制为 5 星
   ClearPlayerWantedLevel(playerId) -- 抹去当前残留警星
   SetPoliceIgnorePlayer(playerId, false) -- 重新允许被 NPC 警察通缉与攻击
   ```
3. 嫌疑人彻底洗白并重新接入原生治安网，一旦再次违法，即可重新被 NPC 或玩家警察捕获。
