# v0.7b 收尾 vs v1.0 联调 — 决策建议

> 日期：2026-10-21
> 依据：v0.7a 服务端验收结果（[v0.7a-acceptance-report.md](./v0.7a-acceptance-report.md)）

## 结论

**建议先完成 v0.7b 收尾与 v0.7a 客户端验收，再启动 v1.0 联调。**

不建议现在直接进入 v1.0：服务端基线已绿，但客户端交互与部署产物仍未验证，直接联调会把“环境问题”和“系统问题”混在一起。

## 依据

| 事实 | 影响 |
|------|------|
| 服务端启动 79 资源无报错，`/test run all` 225 PASS / 0 FAIL | 具备稳定基线 |
| `tcity-dashboard` v2.1 已启用，但未做真人客户端验收 | v0.7b 只差验收，收尾成本低 |
| 车店 NUI / 车库 / 物流 / 手机仍有 6 项客户端流程未验 | v1.0 联调前必须清掉 |
| `oxmysql/dist`、`menuv/dist`、`tcity-dashboard/nui/dist` 未入库 | 新克隆/CI 会缺运行时文件 |
| 132 个 DB 用例因缺 `mysql-connector-python` 跳过 | 持久化回归覆盖不足 |
| v0.6a / v0.6b 仍为部分落地 | v1.0 范围需先冻结 |

## 建议顺序

1. **补齐部署产物**：将 3 个 `dist` 目录纳入版本管理或 release 附件；在 CI 中校验 `resources/[standalone]/oxmysql/dist/build.js` 存在。
2. **跑完 132 个 DB 用例**：在一次性测试库安装 `mysql-connector-python` 后执行，避免污染开发库。
3. **v0.7a 客户端验收**：车店 NUI（购车/分期/试驾/换车）、车库、物流全流程、手机真实收发。
4. **v0.7b 验收**：中控屏 6 类模板、警用控制台（ANPR/雷达/追踪/CCTV）、与 `custom-vehicles` 的钥匙/警笛联动。
5. **冻结 v1.0 范围**：把 v0.6a/v0.6b 未完成项明确为“上线后迭代”，避免范围蔓延。
6. **v1.0 联调**：100 人并发、DB QPS/刷盘延迟、重启与回档、txAdmin 关服刷盘、日志与审计。

## 风险

- 若跳过第 1 步，CI 与 fresh clone 会在 `oxmysql` 启动阶段失败。
- 若跳过第 3/4 步，v1.0 压测无法区分“性能瓶颈”与“未验收功能”。
- 8 个手机 SKIP 用例需要真人客户端；无客户端环境不要把它们计为通过。
