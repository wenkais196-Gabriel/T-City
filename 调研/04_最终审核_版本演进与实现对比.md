## ⚠️ 部分偏差项 (6 条)

### 1. "三层缓存 Hot/Warm/Cold" → 实际为 Memory + Dirty Marking 二层

| 报告声明 | 实际代码 |
|:---|:---|
| v0.5 实现了 Hot/Warm/Cold 三层缓存 | `dirty_flush.lua` 只有 `_dirty` 单层脏标记池；standards 中虽提了 Hot/Warm/Cold 概念模型，但代码实现为 Memory-First + IsDirty 二层 |

**影响**: 低。功能上 Memory-First + DirtyFlush 已能达到大部分性能目标，三层缓存属于架构演进方向而非当前实现。

**整改建议**: 更新报告措辞为"内存优先 + 脏标记异步刷盘"；Hot/Warm/Cold 作为 Phase 2 缓存分层演进计划。

---

### 2. "定时 60s 脏数据聚合写盘" → 实际默认 900s (15 分钟)

| 报告声明 | 实际代码 |
|:---|:---|
| v0.5 定时 60s 刷盘 | `dirty_flush.lua:190` — `GetIntConvar('dirty_flush_tick_interval', 900)` |

**影响**: 低-正面。15 分钟比 60 秒更优（减少 DB 写入 15 倍），但报告数字不准确。

**整改建议**: 更正为 900s，并说明可通过 Convar `dirty_flush_tick_interval` 动态调节。

## ❌ 关键错误/未实现 (3 条)

### 🔴 严重：`AddScaledMoney` 完全不存在 — 全局空引用链

**这是本次审计发现的最严重问题。**

搜索范围 `T-CityLite.base/resources/`（3742 文件），结果：

```
搜索 "exports('AddScaledMoney'"         → 0 matches
搜索 "function.*AddScaledMoney"         → 0 matches
搜索 "custom-main" 中的 AddScaledMoney → 0 matches (across 10 files)
```

**没有任何资源定义或导出 `AddScaledMoney` 函数。**

然而以下 5 个文件在生产代码中调用了它：

| 调用方 | 调用代码 | Fallback |
|:---|:---|:---|
| `custom-crime/server/crime.lua:290` | `exports['custom-main']:AddScaledMoney(src, 'bank', ...)` | `Player.Functions.AddMoney(...)` |
| `custom-crime/server/crime.lua:414` | `exports['custom-main']:AddScaledMoney(src, 'bank', ...)` | `Player.Functions.AddMoney(...)` |
| `custom-phone/server/jobboard.lua:187` | `exports['custom-main']:AddScaledMoney(src, 'bank', ...)` | 无 fallback — 静默失败 |
| `custom-quest/server/quest_rewards.lua:51-55` | `exports['custom-economy']:AddScaledMoney(...)` → `exports['custom-main']:AddScaledMoney(...)` | `Player.Functions.AddMoney(...)` |
| `qb-drugs/server/cornerselling.lua:65-66` | `exports['custom-economy']:AddScaledMoney(...)` | `Player.Functions.AddMoney(...)` |
| `qb-pawnshop/server/main.lua:41` | `exports['custom-main']:AddScaledMoney(...)` | 无 fallback — 静默失败 |

**`core-framework/compat.lua:12` 自己承认了这一点**：
```lua
-- 原 triple-hop: compat → custom-main:AddScaledMoney(不存在) → fallback → origAddMoney → Bus.EconomyService
```

**影响分析**：
- 实际运行时 100% 走 `Player.Functions.AddMoney` fallback
- `custom-phone/jobboard.lua` 和 `qb-pawnshop/main.lua` **没有 fallback**，调用失败后 `finalAmount` 为 `nil`，可能导致静默不发钱
- 经济倍率缩放 (`economy_wage_multiplier`) 未生效 — 所有金钱操作都绕过了 `AddScaled` 的倍率乘法

**P0 整改**：在 `core-framework/services/economy_service.lua` 中实现统一的 `AddScaledMoney` 函数，通过 Bus 暴露，并通过 compat 桥接到所有调用方。

## 🔄 与项目 Standards 对齐检查

对照 `docs/standards/README.md` 五层架构模型：

| 层级 | 标准要求 | 实际状态 |
|:---|:---|:---|
| 1. 客户端表现层 | Svelte NUI，严禁高频 Loop | ✅ custom-phone Svelte；custom-vehicles 事件驱动 |
| 2. 安全与接口过滤层 | CheckRateLimit + ValidateSource + 物理坐标 | ✅ custom-security 完整实现 |
| 3. 核心微服务总线层 | Bus 转发，禁止跨资源直调 exports | ⚠️ 仍有 `exports['custom-economy']` 直调 |
| 4. 缓存与数据隔离层 | Hot/Warm 缓存 + DirtyFlush | ✅ Memory-First + DirtyFlush |
| 5. 外部数据持久化层 | 参数化查询 + Webhook 非阻塞 | ✅ oxmysql + PerformHttpRequest |

关键不符合项：第 3 层有跨资源直调 `exports['custom-main']:AddScaledMoney` 且目标不存在。
