**🔴 关键问题：经济出口断裂**

原报告声称 v0.3 "开发了 AddScaledMoney API，受 economy_wage_multiplier 全局 Convar 缩放"——

**事实**：`AddScaledMoney` 函数在任何资源中都不存在。全局搜索 `exports('AddScaledMoney'` 和 `function.*AddScaledMoney` 在 3742 个文件中均为 0 matches。

实际运行路径：
```
所有 AddScaledMoney 调用 → 目标不存在 → 静默 fallback 到 Player.Functions.AddMoney
→ compat.lua 劫持 → Bus.EconomyService.AddMoney → 内存操作
```

这意味着 **`economy_wage_multiplier` 倍率缩放从未生效**。所有经济操作直接以原始金额写入。

**未来开发指导**:
1. **P0**: 在 `core-framework/services/economy_service.lua` 实现 `AddScaledMoney` 全局出口
2. **受影响脚本**: custom-crime (2 处)、custom-phone/jobboard (1 处无 fallback)、custom-quest/quest_rewards (2 处)、qb-drugs/cornerselling (1 处)、qb-pawnshop (1 处无 fallback)
3. **验证方法**: 设置 `economy_wage_multiplier` 为 200，验证任务奖励是否翻倍

### 3.2 ⚡ 三层缓存 — 状态：引擎建成，零消费

**事实**：`core-framework/cache/cache_manager.lua` 实现了 Hot(5s)/Warm(60s)/Cold(300s) 三层 TTL 缓存引擎，fxmanifest 已加载。但全局搜索 `Cache.Hot`/`Cache.Warm`/`Cache.Cold` 仅命中自身 — 零外部消费。

**实际数据流**：
```
Player.Functions.AddMoney
  → compat.lua 劫持
  → Bus.EconomyService.AddMoney
  → Player.PlayerData.money[moneytype] += amount  (直接操作 QBCore 内存)
  → player.IsDirty = true
  → DirtyFlush 900s 定时批量刷盘
```

**裁决**：当前 Memory-First + DirtyFlush 架构在 QBCore/FiveM 场景下是更优选择。`Player.PlayerData` 是框架级常驻内存结构，本身就是一个完美的 Hot 缓存。三层 TTL 缓存在当前场景下是过度工程化——叠加在已有 Hot 层之上不会带来额外性能收益。

**未来方向**：`cache_manager.lua` 标记为"Phase 2 预留基础设施"。当引入需要缓存离线玩家数据的异步任务系统时，Warm/Cold 层才真正发挥作用。当前阶段**不强制接入**。

### 3.3 🧱 custom-crime v2 重构方向 — 状态：已裁决，待 P1 执行

**当前问题**：
- 无 configs.lua — 犯罪类型硬编码

```
├── server/
│   └── main.lua         ← 重构: 标签比对 + 资质门 + Bus 注册

    └── main.lua         ← NEW: PlayerStateBag 监听 + 犯罪身份缓存
```
