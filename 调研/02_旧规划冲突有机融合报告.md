# 🔀 T-City Lite 旧规划冲突与有机融合报告 (v2.0)

在 T-City Lite 的版本演进过程中，由于不同开发阶段和多份设计文档的堆叠，项目内部分别在**毒品产业链**、**驾照获取与车辆钥匙**以及**平民职业**三个领域出现了规划重叠与逻辑脱节。

本报告遵循 **“构建四原则（模块化、高性能、高安全、可扩展）”**，按照 **“数据上下游”** 闭环的思路，对这些冲突进行了有机的融合，给出了最终的技术方案。

---

## 🗺️ 1. 冲突点一：毒品系统 vs Cartel 帮派玩法
* **旧规划冲突**：
  * `v0.5-crime-gameplay.md` 规划了原生 `qb-drugs`（平民或个人在郊区散乱采集、加工、街头 Cornerselling 的模式，单人全闭环）。
  * `ROADMAP.md` Phase 2 规划了 `custom-cartel`（卡特尔集团垄断，集中在 Madrazo 农场，包括配方合成、NPC 盟友、走私运输和警方缉毒联动）。
* **💡 有机融合方案（基于数据上下游的供应链打通）**：
  我们将散乱的个人犯罪与有组织的卡特尔帮派犯罪融合成一条**高关联的社会化工业链条**。

```
【上游：平民生产】
 农民 (custom-quest) 种植农产品 → 产出【化肥 (fertilizer)】 (进入流通)
 卡特尔采购员 (custom-cartel) 向农场 NPC 购买【硫酸/丙酮】
                              │
                              ▼
【中游：帮派加工】
 卡特尔加工点 (Madrazo Ranch 实验室) 消耗 [化肥] + [古柯叶] + [硫酸/丙酮]
 通过 custom-cartel 配方引擎与客户端小游戏，加工制成高浓度【可卡因 (cocaine)】
                              │
                              ▼
【下游：多渠道分销】
 ├─ 渠道 A (散户零售)：卡特尔向下线分发，平民通过 qb-drugs Cornerselling 进行街头交易
 └─ 渠道 B (批量走私)：卡特尔成员承接 custom-quest 的航空走私任务，驾驶飞机越境交付
                              │
                              ▼
【末端：洗钱与审计】
 贩毒获得 [脏钱 (markedbills)] ➔ 送入 Pawnshop 当铺 (custom-crime.LaunderMoney)
 按 75% 比例折算为干净现金，大额操作直接触发 Webhook 审计至 Discord
```

* **四原则对齐**：
  * **模块化**：`custom-cartel` 负责中游提炼与 NPC 盟友管理，`qb-drugs` 仅负责下游 Cornerselling 零售，通过 Bus.MarketService 和物品 ID 解耦。
  * **高安全**：彻底废除客户端传入毒品卖出单价的逻辑，所有单价、化学反应耗时以及配方组成必须由服务端核心配置文件强行核验。
  * **高性能**：加工交互点（Lab）使用 `PolyZone` 和 `qb-target` 触发，完全剔除客户端的高频 $0\text{ms}$ 线程轮询。

## 🗺️ 2. 冲突点二：自动化驾考系统 vs 市政厅直接购买
* **旧规划冲突**：
  * `qb-cityhall` 原生设计为玩家在界面花 $150 即可直接秒买驾驶执照，无任何扮演前置。
  * `driver_plan.md` 和 `pilot_plan.md` 规划了 DMV 驾校科目二、科目三自动化考试，以及飞行学校过圈降落考试。
* **💡 有机融合方案（双轨分流与许可证物理锁定）**：
  保留市政厅的终极买证出口作为“懒人机制”，但通过价格杠杆引导玩家体验自动化驾考任务，同时通过载具引擎和任务系统对许可证进行物理强锁。

```
                        玩家获取驾驶/飞行执照
                                  │
         ┌────────────────────────┴────────────────────────┐
         ▼ 路径 A：自动化技能考试 (推荐)                   ▼ 路径 B：市政厅秒买 (懒人)
 缴纳 $100 报名费，接取 DMV/Pilot 任务             前往市政厅，直接花费 $3,000 / $15,000
 驾驶考车/教练机，通过雷达限速与过圈降落测试       无需进行任何测试，即时通过资金交易拿证
         │                                                 │
         └────────────────────────┬────────────────────────┘
                                  ▼
                调用 custom-certificates 授予 held 状态执照
                                  │
         ┌────────────────────────┴────────────────────────┐
         ▼ 校验应用 1：物理钥匙启动                        ▼ 校验应用 2：承接物流任务
 玩家试图坐进重卡 (Class 10/11) 或飞机 (Class 15/16)      试图在手机 Job Board 承接重卡/走私单
 custom-vehicles 强检，无证直接强制熄火并踢出             custom-quest 强检 min_license，无证拒绝
```

* **四原则对齐**：
  * **高安全**：在客户端进入载具时触发 `CEventNetworkPlayerEnteredVehicle` 瞬间，服务端立刻校验其执照合法性，并在服务端强制断开引擎，防止外挂强开载具。
  * **可扩展**：`custom-certificates` 设计为通用的证件中心，未来可以无缝扩展“武器持有证”、“律师执业证”等，而无需重写驾考系统。

## 🗺️ 3. 冲突点三：平民职业 vs 通用任务系统
* **旧规划冲突**：
  * 游戏初期保留了原生的 `qb-busjob`、`qb-towjob`、`qb-garbagejob` 等独立脚本资源，各脚本手写了大量高度类似的“坐标点判定 -> 进度条 -> 加钱”逻辑。
  * `overall_plan.md` 规划将所有的平民工作“轻量任务化”，收归到 `custom-quest` 状态机。
* **💡 有机融合方案（职业脚本卸载与纯配置化包装）**：
  完全卸载并禁用原版臃肿的 `qb-` 平民职业资源。将所有的平民执勤逻辑（公交线打卡、违章拖车、垃圾清运）抽象为 `custom-quest` 的 Lua 配置文件。

```
【原版平民职业】 (5 个独立脚本 + 5 个 client 线程轮询 + 重复的 QBCore 加钱) ──► 【彻底废弃 ❌】
                                                                             │
                                                                             ▼
【融合方案】
 统一由 `custom-quest` 读取 `configs/quests/` 下的配置 (如 `bus_route_mission.lua`)
 ├─ 任务步骤定义为 15 个 `reach` 类型节点 (公交站坐标 + blip 提示)
 ├─ 交互步骤定义为 `interact` 类型节点 (搬运垃圾箱进度条)
 └─ 最终结算调用 `AddScaledMoney` (挂接市长 KPI 反哺机制)
                                                                             ▲
                                                                             │
【开发优势】 ─────────────────────────────────────────────────────────────────┘
 1. 0 冗余代码：状态流转、断线保护、DB 持久化全部共用任务系统的底层。
 2. 0 线程浪费：没有任务激活时，客户端没有任何 Tick 在运行，性能开销降为 0。
```

* **四原则对齐**：
  * **模块化**：所有的平民职业退化为“任务系统的数据插槽（Data Slot）”，实现真正的逻辑与数据解耦。
  * **高性能**：原版 5 个职业资源运行时占用的 CPU 周期全部归零，由 `custom-quest` 的单一事件监听器统一代理。
